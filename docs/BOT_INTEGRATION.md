# 飞书 / Lark、钉钉、企业微信接入指南

本文说明如何把飞书 / Lark、钉钉和企业微信接入 Steam Games Monitor。项目里有两套互不替代的能力，请先确认目标：

| 目标 | 平台侧应创建 | 系统入口 | 方向 |
| --- | --- | --- | --- |
| 接收发售、促销、下架等事件提醒 | 群自定义机器人 / 群机器人 Webhook | **通知渠道** | 单向：系统 → 群 |
| 在聊天中发送 `/add`、`/list` 等指令 | 飞书 / Lark 企业自建应用 / 钉钉企业内部机器人（Outgoing） / 企业微信智能机器人（长连接） | **指令机器人** | 双向：平台 → 系统 → 平台 |

> 群机器人 Webhook 通常只能发送消息，不能接收指令。飞书 / Lark 可扫码一键创建应用，并选择 HTTP 回调或 WebSocket 长连接；钉钉需要创建应用并配置回调地址；企业微信需要创建智能机器人并使用长连接。
>
> 通知渠道与指令机器人是两套独立配置：同一个平台可以只配通知，也可以只配指令，或两者都配。

---

## 1. 通用准备

### 1.1 公网 HTTPS 与 PUBLIC_BASE_URL（HTTP 回调模式）

使用 **HTTP 回调** 的飞书 / Lark / 钉钉需要平台主动把消息推送到你的服务器，因此必须满足：

- 服务可从公网访问，并使用平台认可的 **HTTPS** 地址。
- `.env` 中的 `PUBLIC_BASE_URL` 与浏览器实际访问地址一致，例如 `https://steam.example.com`。
- 不要使用默认的 `http://localhost:8787`，否则系统生成的回调地址平台无法访问。
- 建议使用独立域名或子域名。回调路径固定为 `/webhooks/...`，不要部署在需要额外重写的子路径下。

系统中显示的回调地址由以下规则生成：

```text
飞书 / Lark  https://<PUBLIC_BASE_URL 的域名>/webhooks/feishu/<slug>
钉钉         https://<PUBLIC_BASE_URL 的域名>/webhooks/dingtalk/<slug>
```

`<slug>` 在创建机器人时随机生成，每个机器人不同。修改 `PUBLIC_BASE_URL` 后回调地址会变化，需要同步更新平台后台。

> 飞书 / Lark 的**长连接模式**和企业微信智能机器人都由服务端主动建立出站连接，不需要公网回调地址、公网 IP、Token 或 EncodingAESKey。扫码创建的飞书 / Lark 应用默认使用长连接。
>
> 但 `PUBLIC_BASE_URL` 仍必须能被机器人的所有者在浏览器中访问：未授权用户收到的网页授权链接会使用该地址。

### 1.2 反向代理要求

Nginx、Caddy、Traefik 或云负载均衡需要满足（仅影响飞书 / Lark / 钉钉的 HTTP 回调）：

- **原样转发请求体**，不要重新序列化 JSON、不要压缩或修改内容；飞书 / Lark 和钉钉的签名基于原始请求体。
- 保留平台请求头：飞书的 `X-Lark-Request-Timestamp`、`X-Lark-Request-Nonce`、`X-Lark-Signature`，钉钉的 `timestamp`、`sign`。
- 保留查询参数，不要丢失签名参数。
- 不要给 `/webhooks/*` 增加登录、Basic Auth、HTML 跳转或 WAF 交互验证。
- 请求体上限至少 1 MB；读取超时不少于 10 秒。
- 使用受信任的 TLS 证书，平台会校验证书链。

飞书 / Lark 长连接与企业微信长连接不经过反向代理，只需要服务器能出站访问对应平台（Lark 使用 `open.larksuite.com`）。

### 1.3 时间同步与密钥

- 服务器需开启 NTP 时间同步。飞书 / Lark 签名允许 ±300 秒偏差，钉钉 Outgoing 回调允许 ±1 小时偏差。
- `APP_SECRET`（至少 32 字符）用于加密保存渠道和机器人凭据。**不要随意更换或丢失**：更换后已保存的 App Secret、机器人 Secret、Encrypt Key 等将无法解密，只能重新填写。
- 机器人凭据保存在 SQLite 中，使用 AES-256-GCM 加密；API 和页面不会回显明文，编辑时留空表示保留原值。

### 1.4 推荐创建顺序

飞书 / Lark（扫码，推荐）：

1. 在「指令机器人」点击「飞书 / Lark 扫码」，选择飞书或 Lark 国际版并扫码。
2. 在平台页面创建应用并确认；系统自动写入 App ID / App Secret、所有者 `open_id`，并启用长连接。
3. 在飞书 / Lark 中搜索应用名称开始单聊，或把机器人加入群聊。
4. 发送 `/help` 验证指令与回复链路。

飞书 / Lark（手动）：

1. 在系统中创建机器人，选择版本（飞书 / Lark）和事件接收方式（HTTP 回调 / 长连接）。
2. HTTP 回调：复制回调地址填入平台后台，并配置 Encrypt Key / Verification Token；长连接：在平台选择「使用长连接接收事件」。
3. 订阅 `im.message.receive_v1`，申请消息读取与发送权限。
4. 发布应用、添加机器人到群或设置可见范围。
5. 发送 `/help` 验证。

钉钉：

1. 在系统中创建机器人，复制回调地址。
2. 到平台后台创建应用 / 机器人，填写回调地址和密钥。
3. 平台保存回调时通常会发起 URL 验证；确保系统已启动、机器人处于启用状态。
4. 在平台发布应用、添加机器人到群或设置可见范围。
5. 发送 `/help` 验证指令与回复链路。

企业微信：

1. 在企业微信管理后台创建智能机器人，选择 API 模式 → 长连接，获取 Bot ID 和 Secret。
2. 在系统中创建「企业微信智能机器人（长连接）」，填写 Bot ID、Secret 和所有者 UserID。
3. 保存后系统自动建立长连接，无需平台 URL 验证。
4. 将机器人加入群聊或单聊，发送 `/help` 验证。

## 2. 通知渠道（单向推送）

通知渠道用于把监控事件推送到群聊，不需要公网回调地址，只需要平台提供的 Webhook URL。

### 2.1 三种群机器人对比

| 平台 | 系统类型 | 消息格式 | 签名 | 说明 |
| --- | --- | --- | --- | --- |
| 企业微信 | 企业微信群机器人 | markdown | 无 | 单条约 4096 字节，系统会截断；群机器人只能发送 |
| 飞书 | 飞书机器人（自定义机器人） | 交互卡片 | 可选签名密钥 | 可开启签名校验；建议开启 |
| 钉钉 | 钉钉机器人（自定义机器人） | markdown | 可选加签密钥 | 可开启加签；系统按钉钉规则计算签名 |

配置入口：左侧 **通知渠道 → 新建渠道**。填写名称、Webhook、可选签名密钥，并勾选需要订阅的事件。

> 事件通知默认通过这里的群机器人 Webhook 发送；「指令机器人」也可以单独开启事件通知，二者相互独立，可同时使用。

### 2.2 企业微信群机器人

1. 打开企业微信群聊 → 群设置 → 群机器人 → 添加机器人。
2. 复制 Webhook 地址（通常形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`）。
3. 在系统「通知渠道」选择 **企业微信群机器人**，粘贴 Webhook 并保存。
4. 点击渠道的「发送测试」确认群内收到消息。

注意：

- Webhook 本身就是凭据，泄露后任何人都能向群里发消息；泄露后请在群内移除并重新添加机器人。
- 群机器人不能接收 `/add` 等指令；需要指令请使用「企业微信智能机器人（长连接）」。
- 单条消息限制约 4096 字节，系统会自动截断，长列表可能显示不全。
- 群机器人有频率限制，触发限流时系统会自动重试。

### 2.3 飞书自定义机器人

1. 打开飞书群 → 群设置 → 群机器人 → 添加机器人 → 自定义机器人。
2. 复制 Webhook 地址（通常形如 `https://open.feishu.cn/open-apis/bot/v2/hook/...`）。
3. 建议在安全设置中选择 **签名校验**，复制签名密钥。
4. 在系统「通知渠道」选择 **飞书机器人**，粘贴 Webhook；如开启签名，填写签名密钥。
5. 保存后发送测试消息。

签名规则（系统已实现，无需手动计算）：

- 时间戳为秒级。
- 以 `timestamp + "\n" + secret` 作为 HMAC-SHA256 的密钥，对空字符串计算签名，结果 Base64 编码。
- 时间戳和签名随消息体一起发送。

若使用「自定义关键词」或「IP 白名单」而不是签名，请确认通知内容包含关键词，或将服务器出口 IP 加入白名单。

### 2.4 钉钉自定义机器人

1. 打开钉钉群 → 群设置 → 智能群助手 → 添加机器人 → 自定义。
2. 复制 Webhook 地址（通常形如 `https://oapi.dingtalk.com/robot/send?access_token=...`）。
3. 建议在安全设置中选择 **加签**，复制加签密钥。
4. 在系统「通知渠道」选择 **钉钉机器人**，粘贴 Webhook；如开启加签，填写加签密钥。
5. 保存后发送测试消息。

签名规则（系统已实现）：

- 时间戳为毫秒级。
- 以 `secret` 为密钥，对 `timestamp + "\n" + secret` 计算 HMAC-SHA256，结果 Base64 编码。
- `timestamp` 和 `sign` 作为 URL 查询参数发送。

若使用「自定义关键词」或「IP 地址段」而不是加签，请相应调整安全设置。触发限流（如错误码 `90037`）时系统会自动重试。

### 2.5 事件订阅与重试

通知渠道可以勾选订阅的事件类型：

| 事件 | 说明 |
| --- | --- |
| `release` | 游戏 / DLC 正式发售 |
| `sale_start` | 折扣达到监控阈值 |
| `sale_change` | 促销中的折扣或价格变化 |
| `sale_end` | 折扣结束、恢复原价 |
| `price_change` | 非促销状态下原价变化或免费状态翻转 |
| `delisting_warning` | Steam 新闻命中下架关键词（启发式，需人工确认） |
| `delisted` | 连续两次确认商店无法购买 |
| `restored` | 恢复可购买 |
| `check_error` | 检查失败 |

- **不勾选任何事件**时，默认接收除 `check_error` 外的全部事件。
- 发送失败会按 30 秒 → 2 分钟 → 10 分钟 → 1 小时 → 6 小时 → 24 小时重试，最多 6 次。
- 每个渠道卡片上有「发送测试」，可用于验证 Webhook 和签名配置。

## 3. 指令机器人（双向）

指令机器人让用户在飞书 / Lark、钉钉或企业微信聊天中通过斜杠指令管理监控项。飞书 / Lark 支持 HTTP 回调或 WebSocket 长连接，钉钉通过 HTTP 回调，企业微信通过 WebSocket 长连接；结果分别通过平台 API 或长连接回复到原会话。

### 3.1 通用行为

- **作用范围**：指令始终作用于机器人所属账号的数据。即使允许名单中的其他管理员使用机器人，也是修改机器人所有者的监控项。
- **所有者**：`ownerPlatformUserId` 对应的平台用户隐式拥有管理员权限，无需加入允许名单。
- **允许名单**：其他平台用户必须加入允许名单，角色为：
  - `admin`：可使用全部指令。
  - `viewer`：只能使用 `/help`、`/list`、`/price`、`/events`。
  - 不在允许名单中的企业微信用户会收到网页授权链接；飞书 / Lark / 钉钉用户会收到联系所有者的提示。
- **事件通知**：机器人可以在编辑页单独开启「接收事件通知」，把事件推送到最近一次被授权用户使用的会话。它和「通知渠道」相互独立，可以同时启用。没有最近会话时不会推送，详见 3.5 节。
- **消息格式**：当前只处理文本消息。图片、文件、富文本、卡片消息会被忽略。
- **指令格式**：以 `/` 或全角 `／` 开头；支持 `/add@机器人`、引号参数、`--flag=value`。
- **去重**：平台重复投递同一条消息时，系统按平台事件 / 消息 ID 去重，只处理一次。
- **限流**：每个平台用户每分钟最多 10 条指令，每个会话每分钟最多 30 条，每个机器人每分钟最多 60 条；触发限流时每分钟最多提示一次。
- **异步回复**：飞书 / Lark / 钉钉回调会先快速返回成功，企业微信消息通过长连接接收；指令在后台执行，结果通过平台 API 或长连接回复。平台显示回复可能有少量延迟。
- **多结果选择**：`/add`、`/adddlc` 按名称搜索命中多个结果时，机器人会返回编号列表；直接回复序号（10 分钟内有效），或发送 `/cancel` 取消。
- **配额**：每个账号最多创建 3 个机器人；同一平台只能有 1 个启用中的机器人（飞书与 Lark 国际版共用「飞书」平台名额）。飞书 / Lark / 钉钉的 HTTP 回调机器人在停用后回调地址立即失效（返回 404）；长连接机器人在停用后连接断开。

### 3.2 飞书 / Lark 应用机器人

飞书 / Lark 需要创建**企业自建应用**，开启机器人能力并订阅消息事件。群自定义机器人 Webhook 不能接收指令。飞书（中国版）使用 `open.feishu.cn` / `accounts.feishu.cn`，Lark 国际版使用 `open.larksuite.com` / `accounts.larksuite.com`；系统内通过机器人配置的「版本」区分。

#### 扫码一键创建（推荐）

1. 在「指令机器人」点击 **飞书 / Lark 扫码**，在弹窗选择「飞书」或「Lark 国际版」。
2. 用对应客户端扫码；页面会预填应用名称并只允许创建新应用。
3. 确认创建后，系统自动获取 App ID / App Secret，写入扫码者 `open_id` 作为所有者，并启用长连接。
4. 二维码 10 分钟内有效；同一平台已有启用机器人或配额已满时会被拒绝。
5. 在飞书 / Lark 中搜索应用名称开始单聊，或添加机器人到群聊，发送 `/help`。

> 扫码创建使用飞书官方 `PersonalAgent` 模板，预置机器人能力、消息权限和 `im.message.receive_v1` 事件，事件接收方式为长连接。若你的企业限制扫码创建，可使用下方手动配置。
>
> 若飞书二维码被 Lark 租户扫描，系统会自动切换到 `accounts.larksuite.com` 继续完成授权。

#### 手动配置

1. 打开[飞书开放平台](https://open.feishu.cn/app)或 [Lark 开放平台](https://open.larksuite.com/app)，创建企业自建应用。
2. 在「添加应用能力」中开启 **机器人**。
3. 在「权限管理」申请消息相关权限：
   - `im:message.p2p_msg:readonly`：读取用户发给机器人的单聊消息。
   - `im:message.group_at_msg:readonly`：接收群聊中 @ 机器人的消息。
   - `im:message:send_as_bot`：以应用身份发送消息。
   - 如后台按场景拆分权限，请同时申请读取消息内容、发送消息对应的权限。
4. 在系统中创建「飞书 / Lark 应用机器人」，选择版本和事件接收方式：
   - **长连接（推荐）**：在平台「事件与回调」选择「使用长连接接收事件」，订阅 `im.message.receive_v1`；无需回调地址。
   - **HTTP 回调**：将系统显示的 `/webhooks/feishu/<slug>` 填为请求地址；如需加密，填写 Encrypt Key 与 Verification Token。
5. 创建版本并发布应用；在「应用可用范围」中确保使用者可用。
6. 将机器人添加到群聊，或直接与机器人单聊。

#### 系统侧字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 名称 | 是 | 仅用于系统内识别 |
| 版本 | 是 | 飞书（中国版）或 Lark（国际版） |
| 事件接收方式 | 是 | HTTP 回调 / 长连接；扫码创建默认长连接 |
| App ID | 建议必填 | 获取 `tenant_access_token`、回复和推送事件所需 |
| App Secret | 建议必填 | 与 App ID 配对 |
| Encrypt Key | HTTP 回调时视平台 | 必须与飞书 / Lark 后台完全一致；启用加密时必填 |
| Verification Token | HTTP 回调时建议 | 与平台一致；用于校验事件来源 |
| 所有者平台用户 ID | 建议填写 | 填飞书 / Lark `open_id`（通常以 `ou_` 开头）；扫码创建会自动填写 |
| API Base URL | 否 | 仅测试 / 代理使用；生产环境留空 |

#### 回调、长连接与签名

- **HTTP 回调**：平台保存事件订阅地址时会发送 `url_verification` 挑战，系统会返回 `challenge`。
  - 配置了 Encrypt Key 时，系统校验请求头签名 `SHA256(timestamp + nonce + encryptKey + rawBody)`，允许 ±300 秒偏差，然后解密密文。
  - 配置了 Verification Token 时，系统校验事件中的 token；不匹配返回 401。
- **长连接**：服务端使用 App ID / App Secret 主动连接飞书 / Lark 的长连接端点；事件经已认证连接推送，不需要验签、公网地址或反向代理。连接状态会显示在机器人卡片上。
- 仅处理 `im.message.receive_v1` 中的文本消息，忽略应用自身发送的消息。
- 回复优先调用「回复消息」接口；失败时回退为向 `chat_id` 发送消息。
- 群聊中需要 **@机器人** 再输入指令；单聊可直接发送。

#### 所有者 ID 与允许名单

- 飞书 / Lark 事件中用户标识优先取 `open_id`，因此所有者 ID 和允许名单应填写 `open_id`，不要填手机号、邮箱或姓名。
- 扫码创建会自动把扫码者的 `open_id` 写入所有者；手动配置时可查看事件调试 / 回调日志，或让用户先发一条消息后查看平台事件详情。

### 3.3 钉钉机器人（Outgoing）

钉钉需要创建**企业内部机器人**并开启 HTTP 回调（Outgoing）。钉钉自定义群机器人 Webhook 不能接收指令。

#### 平台侧配置

1. 打开[钉钉开放平台](https://open.dingtalk.com/)，创建企业内部应用。
2. 为应用添加机器人能力。
3. 在机器人消息接收配置中选择 **HTTP 回调 / Outgoing**（本系统未接入钉钉 Stream 模式），填写系统显示的回调地址。
4. 在系统中创建「钉钉机器人（Outgoing）」，填写与应用一致的 App Secret；如需接收机器人事件通知，同时填写 App Key 和 Robot Code。
5. 发布应用，将机器人添加到群聊。
6. 在群内 **@机器人** 发送 `/help`。

#### 系统侧字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 名称 | 是 | 仅用于系统内识别 |
| App Key（Client ID） | 事件通知必填 | 钉钉应用 App Key；主动事件通知需要与 App Secret、Robot Code 一起配置 |
| App Secret | 是 | 用于校验 Outgoing 回调签名；不是自定义机器人的加签密钥；事件通知也需要 |
| Robot Code | 事件通知必填 | 机器人编码；用于标识与主动发送事件 |
| 所有者平台用户 ID | 建议填写 | 填钉钉 `staffId` |
| API Base URL | 否 | 仅测试 / 代理使用；生产环境留空 |

#### 回调与签名说明

- 钉钉回调请求头包含 `timestamp`（毫秒）和 `sign`。
- 系统按以下规则校验签名，允许 ±1 小时偏差：
  - 以 `App Secret` 为密钥，对 `timestamp + "\n" + App Secret` 计算 HMAC-SHA256。
  - 结果 Base64 编码；请求头中的 `sign` 可能经过 URL 编码，系统会先解码。
- 仅处理 `msgtype = text` 的文本消息。
- 用户 ID 优先取 `senderStaffId`，其次 `senderId`；所有者 ID 和允许名单应填写 `staffId`。
- 回复使用回调中返回的 `sessionWebhook` 发送 markdown，并 @ 指令发送者；该 Webhook 有有效期（通常约 1.5 小时），过期后回复会失败。若指令处理耗时较长或平台重试较晚，重新发送指令即可。
- 回调必须快速返回 `{}`，否则钉钉会重试；系统会按消息 ID 去重。

#### 所有者 ID 与允许名单

- 以回调事件中的 `senderStaffId`（其次 `senderId`）为准；可在开放平台的事件调试日志中查看，或在通讯录成员详情中核对。
- 所有者 ID 只匹配 `senderStaffId` 或 `senderId`，不要填写昵称、手机号或邮箱。

### 3.4 企业微信智能机器人（长连接）

企业微信需要创建**智能机器人**并选择 **API 模式 → 长连接**。企业微信群机器人 Webhook 只能发送，不能接收指令。

> 升级说明：旧版企业微信自建应用回调（Token / EncodingAESKey / CorpID / AgentID）已不再用于指令机器人。已有机器人需要在「指令机器人」中改为填写智能机器人的 Bot ID / Secret 并保存。

#### 扫码添加（推荐）

1. 在系统「指令机器人」页点击 **企微扫码添加**。
2. 使用有创建智能机器人权限的企业微信扫码，按页面提示创建并授权机器人。
3. 系统会自动获取 Bot ID / Secret，创建机器人并建立长连接；二维码 5 分钟内有效。
4. 创建成功后建议点击「编辑机器人」填写所有者企业微信 UserID，或将使用成员加入允许名单。

> 同一平台已有启用中的机器人，或机器人配额已满时，扫码会被拒绝；请先在页面处理旧机器人。
>
> 扫码使用企业微信官方授权页。若账号没有创建智能机器人的权限，或企业微信调整了页面流程，仍可使用下方的手动配置。

#### 手动配置

1. 打开[企业微信管理后台](https://work.weixin.qq.com/)或企业微信客户端工作台，进入「智能机器人」→ 创建机器人。
2. 在创建流程中选择「API 模式创建」→「使用长连接」。
3. 获取并保存 **Bot ID** 和 **Secret**。Secret 通常只显示一次，丢失后可重新生成。
4. 在系统中创建「企业微信智能机器人（长连接）」，填写 Bot ID、Secret 和所有者 UserID。
5. 将机器人添加到群聊或单聊；群聊中 **@机器人** 发送 `/help`。
6. 无需填写回调地址、Token、EncodingAESKey 或 CorpID；服务会主动连接 `wss://openws.work.weixin.qq.com`。

#### 系统侧字段

| 字段 | 是否必填 | 说明 |
| --- | --- | --- |
| 名称 | 是 | 仅用于系统内识别 |
| Bot ID | 是 | 智能机器人的唯一标识 |
| Secret | 是 | 长连接专用 Secret，用于 `aibot_subscribe` 鉴权 |
| 所有者平台用户 ID | 建议填写 | 企业微信通讯录中的成员 UserID；以机器人实际回调中的 `from.userid` 为准 |

#### 长连接机制

- 服务端主动连接 `wss://openws.work.weixin.qq.com`，适配内网部署，不需要固定公网 IP。
- 连接建立后发送 `aibot_subscribe`，使用 Bot ID + Secret 完成身份校验；之后每 30 秒发送 `ping` 心跳。
- 用户消息通过 `aibot_msg_callback` 明文推送，无需解密；系统只处理 `msgtype = text`。
- 回复通过 `aibot_respond_msg` 携带回调中的 `req_id` 发送 markdown；同一 `req_id` 的回复串行发送。
- 一个智能机器人同一时间只允许一条有效长连接；新连接会踢掉旧连接，多实例部署会互相中断。
- 断线会指数退避重连；连续认证失败或连接被新实例替换时，机器人卡片会显示长连接异常。
- 群聊消息会先去掉开头的 `@机器人`，再按斜杠指令解析。
- 消息回调后 24 小时内均可回复；系统在后台队列中执行指令，长指令通常需要几秒。
- 开启机器人事件通知后，系统通过同一长连接使用 `aibot_send_msg` 向最近会话主动推送；需要用户先给机器人发过消息。

#### 所有者 ID 与允许名单

- 填企业微信通讯录中的 **UserID**（成员账号），不要填姓名、手机号或外部联系人 ID。
- 如果机器人创建者不是企业超级管理员，`from.userid` 可能是企业主体下的加密 userid；请以实际回调事件中的值为准配置所有者和允许名单。

#### 未授权与网页授权

- 企业微信用户不在允许名单时，机器人会回复一次性网页授权链接（`PUBLIC_BASE_URL/authorize/<token>`），30 分钟内有效。
- 机器人所有者使用自己的 Web 账号登录链接页面，核对平台用户 ID（以及可用的昵称、会话）后，选择 `viewer` 或 `admin`，再批准或拒绝。
- 非机器人所有者登录后只能查看请求，不能自行批准；需要把链接转发给机器人所有者。
- 授权链接处理一次后失效；同一用户的其它待处理链接会同步更新。过期后请让用户重新发送任意指令生成新链接。
- 扫码创建但尚未填写 `ownerPlatformUserId` 的机器人，所有者可以用自己收到的链接登录并批准自己；如果希望自己拥有全部指令权限，请选择 `admin`。
- `PUBLIC_BASE_URL` 必须可从浏览器访问；如果链接打不开，请检查反向代理和该环境变量。

#### 连接状态

机器人卡片会显示长连接状态：

- **长连接中**：正在建连或自动重连。
- **长连接已连接**：鉴权成功，可以接收指令。
- **长连接异常**：凭据错误、未填写 Bot ID / Secret、网络不可达、认证失败或连接被其他实例替换。
- **长连接未启用**：机器人已停用。

若状态持续异常，请检查 Bot ID / Secret、服务器出站防火墙是否允许 `wss://openws.work.weixin.qq.com:443`，以及是否有其他实例使用了同一个 Bot ID。

### 3.5 机器人事件通知

在「指令机器人」编辑页勾选 **接收事件通知** 后，机器人会额外接收发售、促销、下架等事件。它与通知渠道是两套独立配置，可以同时开启。

- **通知目标**：机器人最近一次被授权用户使用的会话。系统只会在授权用户（所有者或允许名单成员）成功发送指令后更新该目标；未授权用户不会改变通知目标。
- **前置条件**：目标机器人必须先收到过至少一条授权用户的指令，否则不会产生事件投递。机器人卡片会提示“尚未记录最近会话”。
- **事件范围**：接收全部事件，包括检查异常；不支持按机器人单独筛选事件类型。
- **通知渠道的群机器人仍按通知渠道自己的事件勾选规则发送，两者互不影响。**

各平台的额外要求：

- **飞书 / Lark**：需要 App ID / App Secret，并具备以应用身份向会话发送消息的权限。事件发送到最近会话的 `chat_id`；HTTP 回调与长连接模式均可。
- **钉钉**：需要 App Key、App Secret、Robot Code，并具备机器人主动发送消息权限。群聊使用 `openConversationId`，单聊使用发送者 `staffId`。
- **企业微信**：使用长连接 `aibot_send_msg` 推送到最近会话；单聊 `chat_type=1`，群聊 `chat_type=2`。用户必须先与机器人有过会话。

> 如果机器人被停用、事件通知开关关闭、最近会话被删除或机器人被移出群聊，投递会取消或失败；重新让授权用户发送一条指令即可刷新目标会话。

## 4. 指令速查

```text
/help
/add <appid | 商店链接 | 名称> [--discount N] [--note 文本] [--force]
/adddlc <基础游戏 appid | 链接 | 名称> [--max 50]
/remove <id | appid | 名称>
/pause <id | appid | 名称>
/resume <id | appid | 名称>
/check <id | appid | 名称>
/price <id | appid | 名称>
/list [--all] [--sale] [--paused] [--page N]
/events [--item id] [--limit 10]
/cancel
```

说明：

- `/add` 支持直接搜索 Steam 商店；按名称搜索返回多个结果时，回复序号选择。
- `--discount N` 设置折扣通知阈值（0–100），不填使用账号默认值。
- `--force` 用于当前区域无法获取、但仍想添加并只做新闻预警的场景。
- `/adddlc` 会导入基础游戏的全部 DLC，单次最多 50 个。
- `/check` 会绕过缓存立即检查并写入事件，受 Steam 限流影响。
- `/list` 默认不显示已暂停项；`--all` 显示全部，`--sale` 只看促销中，`--paused` 只看暂停项。
- `/events` 默认显示最近 10 条，最多 20 条。
- 查看者权限仅限 `/help`、`/list`、`/price`、`/events`。

## 5. 常见问题排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 飞书 / Lark / 钉钉保存回调地址失败 | 服务不可公网访问、证书无效、`PUBLIC_BASE_URL` 错误 | 用手机流量访问回调域名；确认 HTTPS 证书链完整；确认机器人已创建并启用 |
| 飞书 / Lark / 钉钉回调返回 404 | 机器人被停用、删除，或 `<slug>` 填错 | 在「指令机器人」页面复制最新回调地址；启用机器人 |
| 飞书 / Lark 提示挑战失败 / 401 | Verification Token 或 Encrypt Key 不一致；代理改写了请求体 | 两边重新核对；关闭请求体压缩 / 重写；保留 `X-Lark-*` 请求头 |
| 飞书 / Lark 开启加密后机器人无反应 | 平台开启了 Encrypt Key，但系统未填写，密文无法解析；也可能因 Verification Token 校验直接返回 401 | 在系统填写相同的 Encrypt Key 和 Verification Token，或关闭平台加密后重新保存 |
| 飞书 / Lark 能收消息但无法回复 | App ID / App Secret 未填，或缺少发消息权限 | 补全凭据；在开放平台申请并发布消息发送权限 |
| 飞书 / Lark 长连接一直显示连接中 / 异常 | App ID / App Secret 错误；应用未开启「使用长连接接收事件」；企业限制扫码创建 | 核对凭据；在事件与回调切换为长连接并发布版本；或改用 HTTP 回调 |
| 扫码后搜索不到飞书 / Lark 机器人 | 应用未发布或可用范围不包含该成员 | 在开放平台创建版本并发布，调整可用范围；使用应用名称搜索 |
| 扫了飞书二维码但创建的是 Lark 应用 | 扫码账号属于 Lark 租户，系统自动切换了授权域 | 属正常行为；到 Lark 中搜索应用名称即可 |
| 钉钉回调 401 | App Secret 填错；请求头被代理删除；服务器时间偏差超过 1 小时 | 核对应用 App Secret（不是加签密钥）；保留 `timestamp`、`sign`；同步 NTP |
| 钉钉回复超时 / 失败 | `sessionWebhook` 已过期 | 重新发送指令；确保回调在数秒内完成 |
| 企业微信长连接未连接 / 异常 | Bot ID 或 Secret 填错；服务器无法出站访问 `openws.work.weixin.qq.com:443`；另一个实例使用了同一机器人；机器人已停用 | 核对 Bot ID / Secret；检查出站防火墙与代理；确认没有重复部署；在机器人卡片查看状态与错误信息 |
| 企业微信消息无回复 | 长连接已断开；消息超过 24 小时回复窗口；处理过程中机器人被停用或删除 | 查看长连接状态；重新发送指令；确认机器人保持启用 |
| 企业微信提示连接被替换 | 同一个 Bot ID 建立了新连接，旧连接被企业微信踢下线 | 每个机器人只保留一个运行实例；关闭重复部署的服务，或在系统停用后重新启用 |
| 指令无响应 | 群聊未 @ 机器人；消息不是文本；未以 `/` 开头；用户不在允许名单 | 在群里 @机器人；发送 `/help`；将平台用户 ID 加入允许名单 |
| 所有者没有管理员权限 | 所有者 ID 与平台实际 ID 格式不一致 | 飞书填 `open_id`；钉钉填 `staffId`；企业微信填 `UserID`（或实际回调中的加密 userid） |
| 创建机器人冲突 | 同一平台已有启用中的机器人 | 先停用旧机器人，再启用新机器人 |
| 通知渠道测试失败 | Webhook 失效、签名密钥错误、关键词 / IP 白名单限制 | 重新复制 Webhook；核对签名密钥；检查平台安全设置 |
| 群内没有任何事件通知 | 渠道停用、事件类型未勾选、群机器人被移除 | 检查渠道状态与事件订阅；重新发送测试消息 |
| 机器人没有推送事件通知 | 未开启“接收事件通知”；没有最近授权会话；钉钉缺少 App Key / Robot Code；机器人被停用 | 编辑机器人开启通知；让授权用户先发一条指令；补全钉钉凭据；检查投递记录 |
| 飞书 / Lark / 钉钉重复推送同一条消息 | 平台未及时收到 ACK 或网络抖动 | 系统按消息 ID 去重；确保回调在 10 秒内返回 |

### 调试建议

1. 先使用系统「指令机器人」卡片中的 **模拟指令**，以机器人所有者身份本地执行，确认指令逻辑和配额正常。
2. 再使用「通知渠道」的 **发送测试** 验证 Webhook 和签名。
3. 最后到平台聊天中发送 `/help`，确认回调 / 长连接、权限和回复链路。
4. 查看容器日志：`docker compose logs -f steam-monitor`，关注 `wecom`、`webhook`、`inbound`、`delivery` 相关日志。

## 6. 安全建议

- 飞书 / Lark / 钉钉回调地址、群机器人 Webhook、企业微信 Bot ID / Secret 都视为凭据，不要提交到公开仓库或发到公开群。
- 飞书 / Lark 的 HTTP 回调建议启用 Encrypt Key + Verification Token；长连接凭据同样需要保密。钉钉必须填写 App Secret 验签；企业微信必须保护 Bot ID 与长连接 Secret。
- 允许名单遵循最小权限：普通成员使用 `viewer`，仅管理员使用 `admin`。
- 不要在公网暴露 SQLite 文件；定期备份数据库，并同时备份 `.env` 中的 `APP_SECRET`。
- 修改 `PUBLIC_BASE_URL` 或更换域名后，及时更新飞书 / Lark / 钉钉后台的回调地址；长连接模式不受影响。
- 怀疑凭据泄露时：飞书 / Lark 重置 App Secret / Encrypt Key，钉钉重置 App Secret，企业微信重新生成智能机器人 Secret，并在系统中重新填写。
