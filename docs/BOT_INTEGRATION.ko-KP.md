# 페이수 / Lark, 딩딩, 기업위신접속지침

[简体中文](BOT_INTEGRATION.md) | [繁體中文](BOT_INTEGRATION.zh-TW.md) | [English](BOT_INTEGRATION.en.md) | [Deutsch](BOT_INTEGRATION.de.md) | [Français](BOT_INTEGRATION.fr.md) | [Italiano](BOT_INTEGRATION.it.md) | [日本語](BOT_INTEGRATION.ja.md) | [한국어](BOT_INTEGRATION.ko.md) | [조선어](BOT_INTEGRATION.ko-KP.md) | [Nederlands](BOT_INTEGRATION.nl.md) | [Русский](BOT_INTEGRATION.ru.md)

본문은 페이수 / Lark, 딩딩과 기업위신을 Steam Games Monitor에 접속하는 방법을 설명합니다. 프로젝트에는 서로 대체할수 없는 두가지 기능이 있으므로 먼저 목표를 확정하십시오.

| 목표 | 플래트홈측에서 창조할것 | 체계입구 | 방향 |
| ----------------------------------- | ---------------------------------------------------------------------------------------- | -------------- | ------------------------ |
| 발매, 할인, 내리기 등 사건알림접수 | 단체대화방리용자정의로보트 / 단체대화방로보트 Webhook | **통지경로** | 한방향: 체계 → 단체대화방 |
| 대화에서 `/add`, `/list` 등 명령발송 | 페이수 / Lark기업자체응용 / 딩딩기업내부로보트(Outgoing) / 기업위신지능로보트(긴련결) | **명령로보트** | 쌍방향: 플래트홈 → 체계 → 플래트홈 |

> 단체대화방로보트 Webhook은 보통 메쓰지만 보낼수 있고 명령은 받을수 없습니다. 페이수 / Lark, 딩딩은 모두 스캔부호로 응용을 한번에 창조할수 있으며 HTTP콜백 또는 긴련결을 선택할수 있습니다. 기업위신은 지능로보트를 만들어 긴련결을 리용해야 합니다.
>
> 통지경로와 명령로보트는 두가지 독립적인 설정입니다. 같은 플래트홈에 통지만 설정하거나 명령만 설정하거나 둘 다 설정할수 있습니다.

## 1. 일반준비

### 1.1 공용망 HTTPS와 PUBLIC_BASE_URL(HTTP콜백모식)

**HTTP콜백**을 리용하는 페이수 / Lark / 딩딩은 플래트홈이 메쓰지를 당신의 봉사기로 자발적으로 밀어보내야 하므로 다음을 만족해야 합니다.

- 봉사를 공용망에서 접근할수 있고 플래트홈이 인정하는 **HTTPS**주소를 리용해야 합니다.
- `.env`의 `PUBLIC_BASE_URL`이 브라우제가 실제로 접근하는 주소와 일치해야 합니다(례를 들면 `https://steam.example.com`).
- 기본값 `http://localhost:8787`을 리용하지 마십시오. 그렇지 않으면 체계가 생성한 콜백주소에 플래트홈이 접근할수 없습니다.
- 독립도메인 또는 하위도메인을 리용할것을 권장합니다. 콜백경로는 `/webhooks/...`로 고정되여있으므로 추가개작이 필요한 하위경로에 전개하지 마십시오.

체계에 표시되는 콜백주소는 다음규칙으로 생성됩니다.

```text
페이수 / Lark  https://<PUBLIC_BASE_URL의 도메인>/webhooks/feishu/<slug>
딩딩        https://<PUBLIC_BASE_URL의 도메인>/webhooks/dingtalk/<slug>
```

`<slug>`는 로보트를 창조할 때 임의로 생성되며 로보트마다 다릅니다. `PUBLIC_BASE_URL`을 수정하면 콜백주소가 변하므로 플래트홈배후도 함께 갱신해야 합니다.

> 페이수 / Lark의 **긴련결모식**, 딩딩 **Stream모식**과 기업위신지능로보트는 모두 봉사단이 자발적으로 출발련결을 건립하므로 공용망콜백주소, 공용망 IP, Token 또는 EncodingAESKey가 필요없습니다. 스캔부호로 창조한 페이수 / Lark응용과 딩딩로보트는 기본적으로 긴련결을 리용합니다.
>
> 그러나 `PUBLIC_BASE_URL`은 여전히 로보트소유자가 브라우제에서 접근할수 있어야 합니다. 미허가리용자가 받는 웹페지권한부여련결이 해당주소를 리용하기때문입니다.

### 1.2 반대프록시요구

Nginx, Caddy, Traefik 또는 클라우드부하균형기는 다음을 만족해야 합니다(페이수 / Lark / 딩딩의 HTTP콜백에만 영향).

- **요청본체를 그대로 전달**하고 JSON을 다시 직렬화하거나 내용을 압축, 개작하지 마십시오. 페이수 / Lark와 딩딩의 서명은 원시요청본체에 기초합니다.
- 플래트홈요청머리를 보존하십시오. 페이수의 `X-Lark-Request-Timestamp`, `X-Lark-Request-Nonce`, `X-Lark-Signature`, 딩딩의 `timestamp`, `sign`.
- 조회인수를 보존하고 서명인수를 잃지 마십시오.
- `/webhooks/*`에 로그인, Basic Auth, HTML전환 또는 WAF상호작용검증을 추가하지 마십시오.
- 요청본체상한은 적어도 1 MB, 읽기초과시간은 10초이상.
- 신뢰할수 있는 TLS증서를 리용하십시오. 플래트홈은 증서사슬을 검증합니다.

페이수 / Lark긴련결, 딩딩 Stream과 기업위신긴련결은 반대프록시를 거치지 않으며, 봉사기가 해당플래트홈에 출발접근할수 있으면 됩니다(Lark는 `open.larksuite.com`, 딩딩 Stream은 `api.dingtalk.com`).

### 1.3 시간동기화와 키

- 봉사기는 NTP시간동기화를 켜야 합니다. 페이수 / Lark서명은 ±300초편차를, 딩딩 Outgoing콜백은 ±1시간편차를 허용합니다.
- `APP_SECRET`(적어도 32자)은 경로와 로보트자격증명을 암호화하여 보관하는데 리용합니다. **함부로 바꾸거나 분실하지 마십시오**. 바꾸면 이미 보관된 App Secret, 로보트 Secret, Encrypt Key 등을 해독할수 없어 다시 채워야 합니다.
- 로보트자격증명은 SQLite에 보관되며 AES-256-GCM으로 암호화됩니다. API와 페지는 평문을 표시하지 않으며, 편집할 때 비워두면 원래값을 보존한다는 뜻입니다.

### 1.4 권장창조순서

페이수 / Lark(스캔부호, 권장):

1. 《명령로보트》에서 《페이수 / Lark스캔부호》를 클릭하고 페이수 또는 Lark국제판을 선택한 다음 스캔부호를 찍습니다.
2. 플래트홈페지에서 응용을 창조하고 확인합니다. 체계가 App ID / App Secret과 소유자 `open_id`를 자동으로 기록하고 긴련결을 켭니다.
3. 페이수 / Lark에서 응용이름을 검색하여 개별대화를 시작하거나 로보트를 단체대화방에 추가합니다.
4. `/help`를 보내 명령과 응답경로를 검증합니다.

페이수 / Lark(수동):

1. 체계에서 로보트를 만들고 버전(페이수 / Lark)과 사건접수방식(HTTP콜백 / 긴련결)을 선택합니다.
2. HTTP콜백: 콜백주소를 복사하여 플래트홈배후에 채우고 Encrypt Key / Verification Token을 설정합니다. 긴련결: 플래트홈에서 《긴련결로 사건접수》를 선택합니다.
3. `im.message.receive_v1`을 구독하고 메쓰지읽기와 발송권한을 신청합니다.
4. 응용을 발행하고 로보트를 단체대화방에 추가하거나 가시범위를 설정합니다.
5. `/help`를 보내 검증합니다.

딩딩(스캔부호, 권장):

1. 《명령로보트》에서 《딩딩스캔부호추가》를 클릭하고 휴대전화 딩딩으로 스캔부호를 찍은 다음 창조를 확인합니다.
2. 체계가 Client ID / Client Secret을 자동으로 기록하고 Client ID를 Robot Code로 리용하며 Stream긴련결을 켭니다.
3. 딩딩에서 로보트를 검색하여 개별대화를 시작하거나 로보트를 단체대화방에 추가합니다.
4. `/help`를 보내 검증합니다.

딩딩(수동):

1. 체계에서 로보트를 만들고 메쓰지접수모식을 선택한 다음 콜백주소(HTTP모식)를 복사합니다.
2. 플래트홈배후에서 응용 / 로보트를 만들고 콜백주소와 키를 채우거나 로보트설정에서 Stream모식을 선택합니다.
3. 플래트홈이 콜백을 보관할 때 보통 URL검증을 시작하므로 체계가 시작되여있고 로보트가 리용가능한 상태인지 확인하십시오.
4. 플래트홈에서 응용을 발행하고 로보트를 단체대화방에 추가하거나 가시범위를 설정합니다.
5. `/help`를 보내 명령과 응답경로를 검증합니다.

기업위신:

1. 기업위신관리배후에서 지능로보트를 만들고 API모식 → 긴련결을 선택한 다음 Bot ID와 Secret을 얻습니다.
2. 체계에서 《기업위신지능로보트(긴련결)》를 만들고 Bot ID, Secret과 소유자 UserID를 채웁니다.
3. 보관하면 체계가 자동으로 긴련결을 건립하며 플래트홈 URL검증이 필요없습니다.
4. 로보트를 단체대화방 또는 개별대화에 추가하고 `/help`를 보내 검증합니다.

## 2. 통지경로(한방향밀기)

통지경로는 감시사건을 단체대화방에 밀어보내는데 리용하며, 공용망콜백주소가 필요없고 플래트홈이 제공하는 Webhook URL만 있으면 됩니다.

### 2.1 세가지단체대화방로보트비교

| 플래트홈 | 체계류형 | 메쓰지형식 | 서명 | 설명 |
| -------- | -------------------------- | -------- | ------------ | ---------------------------------------------- |
| 기업위신 | 기업위신단체대화방로보트 | markdown | 없음 | 한건에 약 4096바이트, 체계가 잘라냄; 단체대화방로보트는 발송만 가능 |
| 페이수 | 페이수로보트(리용자정의로보트) | 상호작용카드 | 선택서명키 | 서명검증을 켤수 있음; 켤것을 권장 |
| 딩딩 | 딩딩로보트(리용자정의로보트) | markdown | 선택가입서명키 | 가입서명을 켤수 있음; 체계가 딩딩규칙에 따라 서명을 계산 |

설정입구: 왼쪽 **통지경로 → 새경로**. 이름, Webhook, 선택적서명키를 채우고 구독할 사건을 선택하십시오.

> 사건통지는 기본적으로 여기의 단체대화방로보트 Webhook으로 발송됩니다. 《명령로보트》도 따로 사건통지를 켤수 있으며, 둘은 서로 독립적이여서 동시에 리용할수 있습니다.

### 2.2 기업위신단체대화방로보트

1. 기업위신단체대화방 → 단체대화방설정 → 단체대화방로보트 → 로보트추가를 엽니다.
2. Webhook주소를 복사합니다(보통 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...` 형식).
3. 체계의 《통지경로》에서 **기업위신단체대화방로보트**를 선택하고 Webhook을 붙여넣은 다음 보관합니다.
4. 경로의 《시험발송》을 클릭하여 단체대화방에서 메쓰지를 받았는지 확인합니다.

주의:

- Webhook자체가 자격증명이므로 류출되면 누구나 단체대화방에 메쓰지를 보낼수 있습니다. 류출된 경우 단체대화방에서 로보트를 제거하고 다시 추가하십시오.
- 단체대화방로보트는 `/add` 등 명령을 받을수 없습니다. 명령이 필요하면 《기업위신지능로보트(긴련결)》를 리용하십시오.
- 단일메쓰지제한은 약 4096바이트이며 체계가 자동으로 잘라내므로 긴목록은 일부만 표시될수 있습니다.
- 단체대화방로보트에는 빈도제한이 있으며, 제한에 걸리면 체계가 자동으로 재시도합니다.

### 2.3 페이수리용자정의로보트

1. 페이수단체대화방 → 단체대화방설정 → 단체대화방로보트 → 로보트추가 → 리용자정의로보트를 엽니다.
2. Webhook주소를 복사합니다(보통 `https://open.feishu.cn/open-apis/bot/v2/hook/...` 형식).
3. 안전설정에서 **서명검증**을 선택하고 서명키를 복사할것을 권장합니다.
4. 체계의 《통지경로》에서 **페이수로보트**를 선택하고 Webhook을 붙여넣습니다. 서명을 켰으면 서명키를 채웁니다.
5. 보관한 후 시험메쓰지를 발송합니다.

서명규칙(체계에 이미 실현되여있으므로 수동으로 계산할 필요없음):

- 타임스탬프는 초단위입니다.
- `timestamp + "\n" + secret`을 HMAC-SHA256의 키로 하고 빈 문자열에 대하여 서명을 계산한 다음 결과를 Base64로 부호화합니다.
- 타임스탬프와 서명은 메쓰지본체와 함께 발송됩니다.

서명대신 《리용자정의핵심단어》나 《IP백색명단》을 리용하는 경우 통지내용에 핵심단어가 포함되도록 하거나 봉사기의 출구 IP를 백색명단에 추가하십시오.

### 2.4 딩딩리용자정의로보트

1. 딩딩단체대화방 → 단체대화방설정 → 지능단체대화방조수 → 로보트추가 → 리용자정의를 엽니다.
2. Webhook주소를 복사합니다(보통 `https://oapi.dingtalk.com/robot/send?access_token=...` 형식).
3. 안전설정에서 **가입서명**을 선택하고 가입서명키를 복사할것을 권장합니다.
4. 체계의 《통지경로》에서 **딩딩로보트**를 선택하고 Webhook을 붙여넣습니다. 가입서명을 켰으면 가입서명키를 채웁니다.
5. 보관한 후 시험메쓰지를 발송합니다.

서명규칙(체계에 이미 실현되여있음):

- 타임스탬프는 밀리초단위입니다.
- `secret`을 키로 하고 `timestamp + "\n" + secret`에 대하여 HMAC-SHA256을 계산한 다음 결과를 Base64로 부호화합니다.
- `timestamp`와 `sign`은 URL조회인수로 발송됩니다.

가입서명대신 《리용자정의핵심단어》나 《IP주소대역》을 리용하는 경우 안전설정을 그에 맞게 조정하십시오. 빈도제한(례를 들면 오유코드 `90037`)에 걸리면 체계가 자동으로 재시도합니다.

### 2.5 사건구독과 재시도

통지경로에서는 구독할 사건류형을 선택할수 있습니다.

| 사건 | 설명 |
| ------------------- | ---------------------------------------------- |
| `release` | 게임 / DLC의 정식발매 |
| `release_date` | 정확한 발매일을 확인했거나 발매일이 변경됨 |
| `sale_start` | 할인이 감시기준값에 도달 |
| `sale_change` | 할인중의 할인률 또는 가격변화 |
| `sale_end` | 할인종료, 원래가격회복 |
| `price_change` | 비할인상태에서의 원래가격변화 또는 무료상태전환 |
| `delisting_warning` | Steam소식이 내리기핵심단어에 맞음(발견법, 사람의 확인 필요) |
| `delisted` | 련속 두번 상점에서 구매할수 없음을 확인 |
| `restored` | 구매가능상태회복 |
| `check_error` | 검사실패 |

- **사건을 하나도 선택하지 않으면** 기본적으로 `check_error`를 제외한 모든 사건을 받습니다.
- 발송에 실패하면 30초 → 2분 → 10분 → 1시간 → 6시간 → 24시간 간격으로 재시도하며 최대 6번입니다.
- 모든 경로카드에는 《시험발송》이 있어 Webhook과 서명설정을 검증하는데 리용할수 있습니다.

## 3. 명령로보트(쌍방향)

명령로보트는 리용자가 페이수 / Lark, 딩딩 또는 기업위신대화에서 사선명령으로 감시항목을 관리할수 있게 합니다. 페이수 / Lark는 HTTP콜백 또는 WebSocket긴련결을, 딩딩은 HTTP콜백 또는 Stream긴련결을, 기업위신은 WebSocket긴련결을 지원하며, 결과는 각각 플래트홈 API 또는 긴련결을 통하여 원래대화에 응답됩니다.

### 3.1 공통행위

- **작용범위**: 명령은 항상 로보트소속계정의 데터에 작용합니다. 허용명부의 다른 관리자가 로보트를 리용하더라도 로보트소유자의 감시항목을 수정합니다.
- **소유자식별**: `ownerPlatformUserId`는 스캔한사람 / 로보트소유자를 식별하는데만 리용되며 명령권한을 자동으로 부여하지 않습니다.
- **허용명부**: 모든 플래트홈리용자(소유자 ID 포함)는 허용명부에 들어가야 명령을 실행할수 있으며 역할은 다음과 같습니다.
  - `admin`: 모든 명령을 리용할수 있습니다.
  - `viewer`: `/help`, `/list`, `/price`, `/events`만 리용할수 있습니다.
  - 허용명부에 없는 페이수 / Lark, 딩딩, 기업위신리용자는 한번만 리용할수 있는 웹페지권한부여련결을 받으며 로보트는 원래명령을 실행하지 않습니다. 딩딩도 같은 련결을 지원합니다.
- **사건통지**: 로보트는 편집페지에서 따로 《사건통지접수》를 켜서 사건을 마지막으로 권한부여된 리용자가 리용한 대화에 밀어보낼수 있습니다. 이것은 《통지경로》와 서로 독립적이며 동시에 켤수 있습니다. 최근대화가 없으면 밀어보내지 않으며 자세한 내용은 3.5절을 보십시오.
- **메쓰지형식**: 현재 텍스트메쓰지만 처리합니다. 그림, 화일, 부각텍스트, 카드메쓰지는 무시됩니다.
- **명령형식**: `/` 또는 전각 `／`로 시작하며 `/add@로보트`, 인용부호인수, `--flag=value`를 지원합니다.
- **중복제거**: 플래트홈이 같은 메쓰지를 반복전달할 때 체계는 플래트홈사건 / 메쓰지 ID로 중복을 제거하여 한번만 처리합니다.
- **속도제한**: 플래트홈리용자마다 1분에 최대 10개 명령, 대화마다 1분에 최대 30개, 로보트마다 1분에 최대 60개이며, 제한에 걸리면 1분에 최대 한번만 알립니다.
- **비동기응답**: 페이수 / Lark / 딩딩콜백은 먼저 신속히 성공을 돌려보내고, 딩딩 Stream / 기업위신메쓰지는 긴련결로 접수합니다. 명령은 배경에서 실행되며 결과는 플래트홈 API 또는 긴련결로 응답됩니다. 플래트홈에 표시되는 응답에는 약간의 지연이 있을수 있습니다.
- **여러결과선택**: `/add`, `/adddlc`가 이름검색에서 여러결과에 맞으면 로보트는 번호목록을 돌려보냅니다. 번호를 직접 답하거나(10분동안 유효) `/cancel`을 보내 취소하십시오.
- **배정량**: 계정마다 최대 3개의 로보트를 만들수 있으며, 같은 플래트홈에는 리용중인 로보트가 1개만 있을수 있습니다(페이수와 Lark국제판은 《페이수》플래트홈배정량을 공유). 페이수 / Lark / 딩딩의 HTTP콜백로보트는 정지후 콜백주소가 즉시 무효화되고(404반환), 긴련결 / Stream로보트는 정지후 련결이 끊어집니다.

### 3.2 페이수 / Lark응용로보트(권장)

> #### 권장리유
>
> 페이수/Lark는 개인판을 지원하므로 생활과 사업을 잘 분리할수 있습니다.



페이수 / Lark는 **기업자체응용**을 만들어 로보트기능을 켜고 메쓰지사건을 구독해야 합니다. 단체대화방리용자정의로보트 Webhook은 명령을 받을수 없습니다. 페이수(중국판)는 `open.feishu.cn` / `accounts.feishu.cn`을, Lark국제판은 `open.larksuite.com` / `accounts.larksuite.com`을 리용하며, 체계안에서는 로보트설정의 《버전》으로 구별합니다.

#### 스캔부호로 한번에 창조(권장)

1. 《명령로보트》에서 **페이수 / Lark스캔부호**를 클릭하고 팝업에서 《페이수》 또는 《Lark국제판》을 선택합니다.
2. 해당클리앙트로 스캔부호를 찍습니다. 페지에는 응용이름이 미리 채워지며 새 응용만 창조할수 있습니다.
3. 창조를 확인하면 체계가 App ID / App Secret을 자동으로 얻고 스캔한사람의 `open_id`를 소유자로 기록하며 긴련결을 켭니다.
4. 2차원부호는 10분동안 유효합니다. 같은 플래트홈에 이미 리용중인 로보트가 있거나 배정량이 차면 거절됩니다.
5. 페이수 / Lark에서 응용이름을 검색하여 개별대화를 시작하거나 로보트를 단체대화방에 추가한 다음 `/help`를 보냅니다.

> 스캔부호창조는 페이수공식 `PersonalAgent`주형을 리용하며 로보트기능, 메쓰지권한과 `im.message.receive_v1`사건이 미리 설정되여있고 사건접수방식은 긴련결입니다. 기업에서 스캔부호창조를 제한하는 경우 아래의 수동설정을 리용할수 있습니다.
>
> 페이수2차원부호를 Lark테난트가 찍으면 체계가 자동으로 `accounts.larksuite.com`으로 전환하여 권한부여를 계속 완성합니다.

#### 수동설정

1. [페이수개방플래트홈](https://open.feishu.cn/app) 또는 [Lark개방플래트홈](https://open.larksuite.com/app)을 열고 기업자체응용을 만듭니다.
2. 《응용기능추가》에서 **로보트**를 켭니다.
3. 《권한관리》에서 메쓰지관련권한을 신청합니다.
   - `im:message.p2p_msg:readonly`: 리용자가 로보트에 보낸 개별대화메쓰지를 읽습니다.
   - `im:message.group_at_msg:readonly`: 단체대화방에서 로보트를 @한 메쓰지를 접수합니다.
   - `im:message:send_as_bot`: 응용신분으로 메쓰지를 발송합니다.
   - 배후에서 장면에 따라 권한을 나누어놓은 경우 메쓰지내용읽기와 메쓰지발송에 해당하는 권한도 함께 신청하십시오.
4. 체계에서 《페이수 / Lark응용로보트》를 만들고 버전과 사건접수방식을 선택합니다.
   - **긴련결(권장)**: 플래트홈의 《사건과 콜백》에서 《긴련결로 사건접수》를 선택하고 `im.message.receive_v1`을 구독합니다. 콜백주소가 필요없습니다.
   - **HTTP콜백**: 체계에 표시되는 `/webhooks/feishu/<slug>`를 요청주소로 채웁니다. 암호화가 필요하면 Encrypt Key와 Verification Token을 채웁니다.
5. 버전을 만들어 응용을 발행하고 《응용리용범위》에서 리용자가 리용할수 있도록 하십시오.
6. 로보트를 단체대화방에 추가하거나 로보트와 직접 개별대화합니다.

#### 체계측항목

| 항목 | 필수여부 | 설명 |
| ------------------ | ----------------- | ---------------------------------------------------------------- |
| 이름 | 예 | 체계안에서 식별하는데만 리용 |
| 버전 | 예 | 페이수(중국판) 또는 Lark(국제판) |
| 사건접수방식 | 예 | HTTP콜백 / 긴련결; 스캔부호창조는 기본적으로 긴련결 |
| App ID | 필수에 가까움 | `tenant_access_token`획득, 응답과 사건밀기에 필요 |
| App Secret | 필수에 가까움 | App ID와 한쌍 |
| Encrypt Key | HTTP콜백시 플래트홈에 따름 | 페이수 / Lark배후와 완전히 일치해야 함; 암호화를 켰을 때 필수 |
| Verification Token | HTTP콜백시 권장 | 플래트홈과 일치; 사건출처를 검증하는데 리용 |
| 소유자플래트홈리용자 ID | 채울것을 권장 | 페이수 / Lark `open_id`를 채움(보통 `ou_`로 시작); 스캔부호창조시 자동으로 채워짐 |
| API Base URL | 아니오 | 시험 / 프록시에만 리용; 생산환경에서는 비워둠 |

#### 콜백, 긴련결과 서명

- **HTTP콜백**: 플래트홈이 사건구독주소를 보관할 때 `url_verification`도전을 보내며 체계는 `challenge`를 돌려보냅니다.
  - Encrypt Key를 설정한 경우 체계는 요청머리서명 `SHA256(timestamp + nonce + encryptKey + rawBody)`을 검증하고 ±300초편차를 허용한 다음 암호문을 해독합니다.
  - Verification Token을 설정한 경우 체계는 사건의 token을 검증하며, 일치하지 않으면 401을 돌려보냅니다.
- **긴련결**: 봉사단은 App ID / App Secret으로 페이수 / Lark의 긴련결종단점에 자발적으로 접속합니다. 사건은 이미 인증된 련결로 밀려오므로 서명검증, 공용망주소 또는 반대프록시가 필요없습니다. 련결상태는 로보트카드에 표시됩니다.
- `im.message.receive_v1`의 텍스트메쓰지만 처리하며 응용자신이 보낸 메쓰지는 무시합니다.
- 응답은 우선 《메쓰지응답》인터페히스를 호출하며, 실패하면 `chat_id`에 메쓰지를 보내는것으로 대체합니다.
- 단체대화방에서는 로보트를 **@한 다음** 명령을 입력해야 하며, 개별대화에서는 직접 보낼수 있습니다.

#### 소유자 ID와 허용명부

- 페이수 / Lark사건의 리용자식별은 우선 `open_id`를 취하므로 허용명부에는 `open_id`를 채우고 전화번호, 메일 또는 이름을 채우지 마십시오.
- 스캔부호창조는 스캔한사람의 `open_id`를 《소유자 ID》에 기록하지만 식별에만 리용되며 명령권한을 자동으로 부여하지 않습니다. 처음 리용할 때도 웹페지권한부여를 거쳐 자신의 플래트홈계정을 비준해야 합니다.
- 수동설정시 사건조정 / 콜백록크를 보거나 리용자가 먼저 메쓰지를 하나 보낸 다음 플래트홈사건상세를 볼수 있습니다.

### 3.3 딩딩로보트(HTTP콜백 / Stream)

딩딩은 **기업내부로보트**를 만들어야 하며, 메쓰지접수모식으로 **Stream긴련결**(권장) 또는 **HTTP콜백 / Outgoing**을 선택할수 있습니다. 딩딩리용자정의단체대화방로보트 Webhook은 명령을 받을수 없습니다.

#### 스캔부호추가(권장)

1. 체계의 《명령로보트》페지에서 **딩딩스캔부호추가**를 클릭합니다.
2. 휴대전화 딩딩으로 스캔부호를 찍고 조직을 선택한 다음 페지의 안내에 따라 로보트정보를 채우고 창조를 확인합니다.
3. 체계는 Client ID / Client Secret을 자동으로 얻고 Client ID를 Robot Code로 리용하며 Stream긴련결을 켭니다. 2차원부호는 10분동안 유효합니다.
4. 창조에 성공하면 딩딩에서 로보트를 검색하여 개별대화를 시작하거나 단체대화방에 추가할수 있습니다. 스캔한사람의 `staffId`는 식별에만 리용되며 리용성원은 여전히 웹페지권한부여를 받거나 허용명부에 들어가야 합니다.

> 같은 플래트홈에 이미 리용중인 로보트가 있거나 로보트배정량이 차면 스캔부호가 거절됩니다. 먼저 페지에서 옛 로보트를 처리하십시오.
>
> 스캔부호는 딩딩공식응용등록페지를 리용합니다. 조직에서 스캔부호창조를 제한하거나 등록페지가 이상을 돌려보내는 경우 아래의 수동설정을 리용할수 있습니다.

#### 수동설정

1. [딩딩개방플래트홈](https://open.dingtalk.com/)을 열고 기업내부응용을 만듭니다.
2. 《응용기능추가》에서 **로보트**를 추가합니다.
3. 메쓰지접수모식을 선택합니다.
   - **Stream모식(권장)**: 로보트설정에서 Stream모식을 선택하고 발행합니다. 공용망콜백주소가 필요없습니다.
   - **HTTP콜백 / Outgoing**: 체계에 표시되는 `/webhooks/dingtalk/<slug>`주소를 채우고 App Secret을 채워 서명검증에 리용합니다.
4. 체계에서 《딩딩로보트》를 만들고 Client ID(App Key)와 Client Secret(App Secret)을 채운 다음 같은 접수모식을 선택합니다.
5. 사건통지를 밀어보내려면 Robot Code(보통 Client ID와 같음)를 채우고 응용에 로보트의 자발적메쓰지발송권한이 있는지 확인합니다.
6. 응용을 발행하고 로보트를 단체대화방에 추가한 다음 `/help`를 보냅니다.

#### 체계측항목

| 항목 | 필수여부 | 설명 |
| --------------------------- | ----------------------- | ---------------------------------------------- |
| 이름 | 예 | 체계안에서 식별하는데만 리용 |
| 메쓰지접수모식 | 예 | HTTP콜백 / Stream긴련결; 스캔부호창조는 기본적으로 Stream |
| App Key(Client ID) | Stream시 필수 | 딩딩응용 Client ID; 사건통지에도 필요 |
| App Secret(Client Secret) | Stream시 필수 / HTTP서명검증 | Stream련결자격증명; HTTP콜백에서는 콜백서명검증에 리용 |
| Robot Code | 사건통지시 권장 | 로보트부호; 보통 Client ID와 같음 |
| 소유자플래트홈리용자 ID | 채울것을 권장 | 딩딩 `staffId`를 채움 |
| API Base URL | 아니오 | 시험 / 프록시에만 리용; 생산환경에서는 비워둠 |

#### 메쓰지접수와 응답설명

- **Stream모식**: 봉사단은 Client ID / Secret으로 딩딩 Stream게트웨이에 자발적으로 접속하며 공용망 IP, 도메인 또는 콜백주소가 필요없습니다. 로보트메쓰지는 긴련결로 밀려오며 체계는 즉시 ACK한 다음 명령을 비동기로 실행합니다.
- **HTTP콜백**: 딩딩콜백요청머리에는 `timestamp`(밀리초)와 `sign`이 포함됩니다. 체계는 App Secret을 키로 하고 `timestamp + "\n" + App Secret`에 대하여 HMAC-SHA256을 계산하며 ±1시간편차를 허용합니다.
- 두 모식 모두 `msgtype = text`인 텍스트메쓰지만 처리합니다.
- 리용자 ID는 우선 `senderStaffId`를, 다음으로 `senderId`를 취합니다. 소유자 ID와 허용명부에는 `staffId`를 채우십시오.
- 응답은 메쓰지본체의 `sessionWebhook`으로 markdown을 발송하며 명령발송자를 @합니다. 이 Webhook은 보통 약 1.5시간 유효하며, 만료되면 명령을 다시 보내면 됩니다.
- 체계는 딩딩 `msgId`로 중복을 제거하며, Stream모식은 추가로 밀기를 즉시 확인하여 플래트홈의 반복전달을 피합니다.

#### 소유자 ID와 허용명부

- 콜백사건의 `senderStaffId`(다음으로 `senderId`)를 기준으로 합니다. 개방플래트홈의 사건조정록크에서 보거나 통신록성원상세에서 대조할수 있습니다.
- 《소유자 ID》는 식별에만 리용되며 명령권한을 자동으로 부여하지 않습니다. 모든 딩딩리용자는 웹페지권한부여를 받거나 허용명부에 들어가야 합니다.
- 스캔부호창조가 스캔한사람의 `staffId`를 반드시 돌려보내지는 않으므로 수동으로 보충할수 있습니다. 처음 리용할 때 로보트소속계정으로 웹페지에 로그인하여 비준하면 됩니다.

### 3.4 기업위신지능로보트(긴련결)

기업위신은 **지능로보트**를 만들고 **API모식 → 긴련결**을 선택해야 합니다. 기업위신단체대화방로보트 Webhook은 발송만 할수 있고 명령을 받을수 없습니다.

> 갱신설명: 옛판 기업위신자체응용콜백(Token / EncodingAESKey / CorpID / AgentID)은 더는 명령로보트에 리용되지 않습니다. 기존로보트는 《명령로보트》에서 지능로보트의 Bot ID / Secret을 채우고 보관해야 합니다.

#### 스캔부호추가(권장)

1. 체계의 《명령로보트》페지에서 **기업위신스캔부호추가**를 클릭합니다.
2. 지능로보트창조권한이 있는 기업위신으로 스캔부호를 찍고 페지의 안내에 따라 로보트를 창조하고 권한을 부여합니다.
3. 체계는 Bot ID / Secret을 자동으로 얻고 로보트를 만들어 긴련결을 건립합니다. 2차원부호는 5분동안 유효합니다.
4. 창조에 성공하면 리용성원이 명령을 보내도록 하고 로보트소속계정으로 웹페지에 로그인하여 비준합니다. 소유자 UserID는 식별에만 리용되며 권한을 자동으로 부여하지 않습니다.

> 같은 플래트홈에 이미 리용중인 로보트가 있거나 로보트배정량이 차면 스캔부호가 거절됩니다. 먼저 페지에서 옛 로보트를 처리하십시오.
>
> 스캔부호는 기업위신공식권한부여페지를 리용합니다. 계정에 지능로보트창조권한이 없거나 기업위신이 페지절차를 조정한 경우 아래의 수동설정을 리용할수 있습니다.

#### 수동설정

1. [기업위신관리배후](https://work.weixin.qq.com/) 또는 기업위신클리앙트작업대를 열고 《지능로보트》 → 로보트창조로 들어갑니다.
2. 창조절차에서 《API모식창조》 → 《긴련결리용》을 선택합니다.
3. **Bot ID**와 **Secret**을 얻어 보관합니다. Secret은 보통 한번만 표시되며 분실하면 다시 생성할수 있습니다.
4. 체계에서 《기업위신지능로보트(긴련결)》를 만들고 Bot ID, Secret과 소유자 UserID를 채웁니다.
5. 로보트를 단체대화방 또는 개별대화에 추가합니다. 단체대화방에서는 로보트를 **@하고** `/help`를 보냅니다.
6. 콜백주소, Token, EncodingAESKey 또는 CorpID를 채울 필요가 없습니다. 봉사가 `wss://openws.work.weixin.qq.com`에 자발적으로 접속합니다.

#### 체계측항목

| 항목 | 필수여부 | 설명 |
| ----------------- | -------- | ---------------------------------------------------------------------- |
| 이름 | 예 | 체계안에서 식별하는데만 리용 |
| Bot ID | 예 | 지능로보트의 고유식별자 |
| Secret | 예 | 긴련결전용 Secret, `aibot_subscribe`신분검증에 리용 |
| 소유자플래트홈리용자 ID | 채울것을 권장 | 기업위신통신록의 성원 UserID; 로보트가 실제로 받은 콜백의 `from.userid`를 기준으로 함 |

#### 긴련결기구

- 봉사단은 `wss://openws.work.weixin.qq.com`에 자발적으로 접속하며 내부망전개에 적합하고 고정공용망 IP가 필요없습니다.
- 련결이 건립되면 `aibot_subscribe`를 보내 Bot ID + Secret으로 신분검증을 완성하며, 이후 30초마다 `ping`심장박동을 보냅니다.
- 리용자메쓰지는 `aibot_msg_callback`으로 명문으로 밀려오므로 해독이 필요없으며 체계는 `msgtype = text`만 처리합니다.
- 응답은 `aibot_respond_msg`에 콜백의 `req_id`를 실어 markdown을 발송합니다. 같은 `req_id`의 응답은 차례로 발송됩니다.
- 하나의 지능로보트는 같은 시간에 하나의 유효긴련결만 허용하며, 새 련결은 옛 련결을 끊고 여러실례를 전개하면 서로 중단됩니다.
- 단선되면 간격을 점차 늘여가며 다시 련결하며, 련속인증실패 또는 련결이 새 실례로 대체되면 로보트카드에 긴련결이상이 표시됩니다.
- 단체대화방메쓰지는 먼저 앞부분의 `@로보트`를 제거한 다음 사선명령으로 해석합니다.
- 메쓰지콜백후 24시간안에는 응답할수 있으며, 체계는 배경대기렬에서 명령을 실행하므로 긴명령은 보통 몇초가 걸립니다.
- 로보트사건통지를 켜면 체계는 같은 긴련결로 `aibot_send_msg`를 리용하여 최근대화에 자발적으로 밀어보냅니다. 리용자가 먼저 로보트에 메쓰지를 보낸적이 있어야 합니다.

#### 소유자 ID와 허용명부

- 기업위신통신록의 **UserID**(성원계정)를 채우고 이름, 전화번호 또는 외부련계인 ID를 채우지 마십시오.
- 로보트창조자가 기업의 최고관리자가 아니면 `from.userid`가 기업주체아래의 암호화된 userid일수 있으므로 실제콜백사건의 값을 기준으로 소유자와 허용명부를 설정하십시오.

#### 미허가와 웹페지권한부여

- 기업위신리용자가 허용명부에 없으면 로보트는 한번만 리용할수 있는 웹페지권한부여련결(`PUBLIC_BASE_URL/authorize/<token>`)을 답하며 30분동안 유효합니다.
- 로보트소유자가 자신의 Web계정으로 련결페지에 로그인하여 플래트홈리용자 ID(및 리용가능한 애칭, 대화)를 대조한 다음 `viewer` 또는 `admin`을 선택하고 비준하거나 거절합니다.
- 로보트소유자가 아닌 사람이 로그인하면 요청만 볼수 있고 스스로 비준할수 없으므로 련결을 로보트소유자에게 전달해야 합니다.
- 권한부여련결은 한번 처리하면 무효화되며 같은 리용자의 다른 대기련결도 함께 갱신됩니다. 만료되면 리용자가 임의의 명령을 다시 보내 새 련결을 생성하도록 하십시오.
- 모든 리용성원(스캔한사람자신 포함)은 웹페지권한부여나 허용명부를 거쳐 권한을 얻어야 합니다. 자신에게 모든 명령권한을 주려면 비준할 때 `admin`을 선택하십시오.
- `PUBLIC_BASE_URL`은 브라우제에서 접근할수 있어야 합니다. 련결이 열리지 않으면 반대프록시와 해당환경변수를 확인하십시오.

#### 련결상태

로보트카드에는 긴련결상태가 표시됩니다.

- **긴련결중**: 련결을 건립하거나 자동으로 다시 련결하는중.
- **긴련결접속됨**: 인증에 성공하여 명령을 접수할수 있음.
- **긴련결이상**: 자격증명오유, Bot ID / Secret미기입, 네트웍도달불가, 인증실패 또는 련결이다른실례로 대체됨.
- **긴련결미개시**: 로보트가 정지됨.

상태가 계속 이상이면 Bot ID / Secret, 봉사기출발방화벽에서 `wss://openws.work.weixin.qq.com:443`접근을 허용하는지, 같은 Bot ID를 리용하는 다른실례가 있는지 확인하십시오.

### 3.5 로보트사건통지

《명령로보트》편집페지에서 **사건통지접수**를 선택하면 로보트가 추가로 발매, 할인, 내리기 등 사건을 받습니다. 이것은 통지경로와 두가지 독립적인 설정이며 동시에 켤수 있습니다.

- **통지목표**: 로보트가 마지막으로 허용명부성원에게 리용된 대화. 체계는 권한부여된 리용자가 명령을 성공적으로 보낸후에만 해당목표를 갱신하며, 미허가리용자는 통지목표를 변경하지 않습니다.
- **전제조건**: 목표로보트가 먼저 권한부여된 리용자의 명령을 적어도 하나 받은적이 있어야 하며, 그렇지 않으면 사건전달이 발생하지 않습니다. 로보트카드에는 《아직 최근대화를 기록하지 못하였음》이 표시됩니다.
- **사건범위**: 검사이상을 포함한 모든 사건을 받으며, 로보트별로 사건류형을 따로 여과하는것은 지원하지 않습니다.
- **통지경로의 단체대화방로보트는 여전히 통지경로자신의 사건선택규칙에 따라 발송하며, 둘은 서로 영향을 주지 않습니다.**

각 플래트홈의 추가요구:

- **페이수 / Lark**: App ID / App Secret이 필요하고 응용신분으로 대화에 메쓰지를 보낼 권한이 있어야 합니다. 사건은 최근대화의 `chat_id`로 발송되며 HTTP콜백과 긴련결모식 모두 가능합니다.
- **딩딩**: App Key, App Secret, Robot Code가 필요하고 로보트의 자발적메쓰지발송권한이 있어야 합니다. 단체대화방은 `openConversationId`를, 개별대화는 발송자의 `staffId`를 리용합니다.
- **기업위신**: 긴련결 `aibot_send_msg`로 최근대화에 밀어보내며, 개별대화는 `chat_type=1`, 단체대화방은 `chat_type=2`입니다. 리용자가 먼저 로보트와 대화한적이 있어야 합니다.

> 로보트가 정지되거나 사건통지스위치가 꺼지거나 최근대화가 삭제되거나 로보트가 단체대화방에서 제거되면 전달이 취소되거나 실패합니다. 권한부여된 리용자가 명령을 하나 다시 보내면 목표대화가 갱신됩니다.

```text
/help
/add <appid | 상점련결 | 이름> [--discount N] [--note 본문] [--force]
/adddlc <기본게임 appid | 련결 | 이름> [--max 50]
/remove <id | appid | 이름>
/pause <id | appid | 이름>
/resume <id | appid | 이름>
/check <id | appid | 이름>
/price <id | appid | 이름>
/list [--all] [--sale] [--paused] [--page N]
/events [--item id] [--limit 10]
/cancel
```

설명:

- `/add`는 Steam상점을 직접 검색하는것을 지원하며, 이름검색에서 여러결과가 나오면 번호로 선택합니다.
- `--discount N`은 할인통지기준값(0–100)을 설정하며, 채우지 않으면 계정의 기본값을 리용합니다.
- `--force`는 현재지역에서 얻을수 없지만 추가하여 소식경보만 하고싶은 장면에 리용합니다.
- `/adddlc`는 기본게임의 모든 DLC를 수입하며 한번에 최대 50개입니다.
- `/check`는 캐쉬를 거치지 않고 즉시 검사하여 사건을 기록하며, Steam의 속도제한에 영향을 받습니다.
- `/list`는 기본적으로 정지된 항목을 표시하지 않습니다. `--all`은 전부, `--sale`은 할인중인것만, `--paused`는 정지된 항목만 보여줍니다.
- `/events`는 기본적으로 최근 10개를 표시하며 최대 20개입니다.
- 보는사람권한은 `/help`, `/list`, `/price`, `/events`에만 한정됩니다.

### 조정권장

1. 먼저 체계 《명령로보트》카드의 **모의명령**을 리용하여 로보트소유자신분으로 본지에서 실행하고 명령로직과 배정량이 정상인지 확인합니다.
2. 다음으로 《통지경로》의 **시험발송**을 리용하여 Webhook과 서명을 검증합니다.
3. 마지막으로 플래트홈대화에서 `/help`를 보내 콜백 / 긴련결, 권한과 응답경로를 확인합니다.
4. 콘테나록크를 봄: `docker compose logs -f steam-monitor`, `wecom`, `webhook`, `inbound`, `delivery`관련록크에 주목.

## 6. 안전권장

- 페이수 / Lark / 딩딩콜백주소, 단체대화방로보트 Webhook, 기업위신 Bot ID / Secret은 모두 자격증명으로 간주하여 공개원천저장소에 올리거나 공개단체대화방에 보내지 마십시오.
- 페이수 / Lark의 HTTP콜백은 Encrypt Key + Verification Token을 켤것을 권장하며, 긴련결자격증명도 비밀로 유지해야 합니다. 딩딩 HTTP콜백은 반드시 App Secret을 채워 서명을 검증해야 하고 Stream모식도 Client Secret을 보호해야 합니다. 기업위신은 Bot ID와 긴련결 Secret을 반드시 보호해야 합니다.
- 허용명부는 최소권한을 따르십시오. 일반성원은 `viewer`, 관리자만 `admin`을 리용합니다.
- SQLite화일을 공용망에 폭로하지 마십시오. 데터베스를 정기적으로 예비보관하고 `.env`의 `APP_SECRET`도 함께 예비보관하십시오.
- `PUBLIC_BASE_URL`을 수정하거나 도메인을 바꾼후 페이수 / Lark / 딩딩배후의 콜백주소를 제때 갱신하십시오. 긴련결모식은 영향을 받지 않습니다.
- 자격증명류출이 의심되면 페이수 / Lark는 App Secret / Encrypt Key를 재설정하고, 딩딩은 Client Secret을 재설정하며, 기업위신은 지능로보트 Secret을 다시 생성한 다음 체계에 다시 채우십시오.
