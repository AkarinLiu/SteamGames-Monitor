# 飛書 / Lark、釘釘、企業微信接入指南

[简体中文](BOT_INTEGRATION.md) | [繁體中文](BOT_INTEGRATION.zh-TW.md) | [English](BOT_INTEGRATION.en.md) | [Deutsch](BOT_INTEGRATION.de.md) | [Français](BOT_INTEGRATION.fr.md) | [Italiano](BOT_INTEGRATION.it.md) | [日本語](BOT_INTEGRATION.ja.md) | [한국어](BOT_INTEGRATION.ko.md) | [조선어](BOT_INTEGRATION.ko-KP.md) | [Nederlands](BOT_INTEGRATION.nl.md) | [Русский](BOT_INTEGRATION.ru.md)

[返回 README](../README.zh-TW.md)

本文說明如何把飛書 / Lark、釘釘和企業微信接入 Steam Games Monitor。專案內有兩套互不取代的能力，請先確認目標：

| 目標                                | 平台端應建立                                                                             | 系統入口       | 方向                     |
| ----------------------------------- | ---------------------------------------------------------------------------------------- | -------------- | ------------------------ |
| 接收發售、促銷、下架等事件提醒      | 群組自訂機器人 / 群組機器人 Webhook                                                      | **通知頻道**   | 單向：系統 → 群組        |
| 在聊天中傳送 `/add`、`/list` 等指令 | 飛書 / Lark 企業自建應用 / 釘釘企業內部機器人（Outgoing） / 企業微信智慧機器人（長連線）  | **指令機器人** | 雙向：平台 → 系統 → 平台 |

> 群組機器人 Webhook 通常只能傳送訊息，不能接收指令。飛書 / Lark、釘釘均可掃碼一鍵建立應用，並選擇 HTTP 回呼或長連線；企業微信需要建立智慧機器人並使用長連線。
>
> 通知頻道與指令機器人是兩套獨立設定：同一個平台可以只設定通知，也可以只設定指令，或兩者都設定。

## 1. 通用準備

### 1.1 公網 HTTPS 與 PUBLIC_BASE_URL（HTTP 回呼模式）

使用 **HTTP 回呼** 的飛書 / Lark / 釘釘需要平台主動把訊息推送到你的伺服器，因此必須滿足：

- 服務可從公網存取，並使用平台認可的 **HTTPS** 位址。
- `.env` 中的 `PUBLIC_BASE_URL` 與瀏覽器實際存取的位址一致，例如 `https://steam.example.com`。
- 不要使用預設的 `http://localhost:8787`，否則系統產生的回呼位址平台無法存取。
- 建議使用獨立網域或子網域。回呼路徑固定為 `/webhooks/...`，不要部署在需要額外重寫的子路徑下。

系統中顯示的回呼位址由以下規則產生：

```text
飛書 / Lark  https://<PUBLIC_BASE_URL 的網域>/webhooks/feishu/<slug>
釘釘         https://<PUBLIC_BASE_URL 的網域>/webhooks/dingtalk/<slug>
```

`<slug>` 在建立機器人時隨機產生，每個機器人不同。修改 `PUBLIC_BASE_URL` 後回呼位址會改變，需要同步更新平台後台。

> 飛書 / Lark 的**長連線模式**、釘釘 **Stream 模式** 和企業微信智慧機器人都由伺服器端主動建立對外連線，不需要公網回呼位址、公網 IP、Token 或 EncodingAESKey。掃碼建立的飛書 / Lark 應用和釘釘機器人預設使用長連線。
>
> 但 `PUBLIC_BASE_URL` 仍必須能由機器人的擁有者在瀏覽器中存取：未授權使用者收到的網頁授權連結會使用該位址。

### 1.2 反向代理要求

Nginx、Caddy、Traefik 或雲端負載平衡器需要滿足（僅影響飛書 / Lark / 釘釘的 HTTP 回呼）：

- **原樣轉發請求主體**，不要重新序列化 JSON、不要壓縮或修改內容；飛書 / Lark 和釘釘的簽章基於原始請求主體。
- 保留平台請求標頭：飛書的 `X-Lark-Request-Timestamp`、`X-Lark-Request-Nonce`、`X-Lark-Signature`，釘釘的 `timestamp`、`sign`。
- 保留查詢參數，不要遺失簽章參數。
- 不要給 `/webhooks/*` 增加登入、Basic Auth、HTML 轉址或 WAF 互動驗證。
- 請求主體上限至少 1 MB；讀取逾時不少於 10 秒。
- 使用受信任的 TLS 憑證，平台會驗證憑證鏈。

飛書 / Lark 長連線、釘釘 Stream 與企業微信長連線不經過反向代理，只需要伺服器能對外連線到對應平台（Lark 使用 `open.larksuite.com`，釘釘 Stream 使用 `api.dingtalk.com`）。

### 1.3 時間同步與金鑰

- 伺服器需開啟 NTP 時間同步。飛書 / Lark 簽章允許 ±300 秒誤差，釘釘 Outgoing 回呼允許 ±1 小時誤差。
- `APP_SECRET`（至少 32 字元）用於加密儲存頻道和機器人憑證。**不要任意更換或遺失**：更換後已儲存的 App Secret、機器人 Secret、Encrypt Key 等將無法解密，只能重新填寫。
- 機器人憑證儲存在 SQLite 中，使用 AES-256-GCM 加密；API 和頁面不會顯示明文，編輯時留空表示保留原值。

### 1.4 建議建立順序

飛書 / Lark（掃碼，建議）：

1. 在「指令機器人」點選「飛書 / Lark 掃碼」，選擇飛書或 Lark 國際版並掃碼。
2. 在平台頁面建立應用並確認；系統自動寫入 App ID / App Secret、擁有者 `open_id`，並啟用長連線。
3. 在飛書 / Lark 中搜尋應用名稱開始一對一聊天，或把機器人加入群組聊天。
4. 傳送 `/help` 驗證指令與回覆鏈路。

飛書 / Lark（手動）：

1. 在系統中建立機器人，選擇版本（飛書 / Lark）和事件接收方式（HTTP 回呼 / 長連線）。
2. HTTP 回呼：複製回呼位址填入平台後台，並設定 Encrypt Key / Verification Token；長連線：在平台選擇「使用長連線接收事件」。
3. 訂閱 `im.message.receive_v1`，申請訊息讀取與傳送權限。
4. 發布應用、將機器人加入群組或設定可見範圍。
5. 傳送 `/help` 驗證。

釘釘（掃碼，建議）：

1. 在「指令機器人」點選「釘釘掃碼新增」，用手機釘釘掃碼並確認建立。
2. 系統自動寫入 Client ID / Client Secret，並以 Client ID 作為 Robot Code，啟用 Stream 長連線。
3. 在釘釘中搜尋機器人開始一對一聊天，或將機器人加入群組聊天。
4. 傳送 `/help` 驗證。

釘釘（手動）：

1. 在系統中建立機器人，選擇訊息接收模式，複製回呼位址（HTTP 模式）。
2. 到平台後台建立應用 / 機器人，填寫回呼位址和金鑰，或在機器人設定中選擇 Stream 模式。
3. 平台儲存回呼時通常會發起 URL 驗證；確保系統已啟動、機器人處於啟用狀態。
4. 在平台發布應用、將機器人加入群組或設定可見範圍。
5. 傳送 `/help` 驗證指令與回覆鏈路。

企業微信：

1. 在企業微信管理後台建立智慧機器人，選擇 API 模式 → 長連線，取得 Bot ID 和 Secret。
2. 在系統中建立「企業微信智慧機器人（長連線）」，填寫 Bot ID、Secret 和擁有者 UserID。
3. 儲存後系統自動建立長連線，無需平台 URL 驗證。
4. 將機器人加入群組聊天或一對一聊天，傳送 `/help` 驗證。

## 2. 通知頻道（單向推送）

通知頻道用於把監控事件推送到群組聊天，不需要公網回呼位址，只需要平台提供的 Webhook URL。

### 2.1 三種群組機器人比較

| 平台     | 系統類型                   | 訊息格式 | 簽章         | 說明                                           |
| -------- | -------------------------- | -------- | ------------ | ---------------------------------------------- |
| 企業微信 | 企業微信群組機器人         | markdown | 無           | 單則約 4096 位元組，系統會截斷；群組機器人只能傳送 |
| 飛書     | 飛書機器人（自訂機器人）   | 互動卡片 | 可選簽章金鑰 | 可開啟簽章驗證；建議開啟                       |
| 釘釘     | 釘釘機器人（自訂機器人）   | markdown | 可選加簽金鑰 | 可開啟加簽；系統依釘釘規則計算簽章             |

設定入口：左側 **通知頻道 → 新增頻道**。填寫名稱、Webhook、可選簽章金鑰，並勾選需要訂閱的事件。

> 事件通知預設透過這裡的群組機器人 Webhook 傳送；「指令機器人」也可以單獨開啟事件通知，兩者相互獨立，可同時使用。

### 2.2 企業微信群組機器人

1. 開啟企業微信群組聊天 → 群組設定 → 群組機器人 → 新增機器人。
2. 複製 Webhook 位址（通常形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`）。
3. 在系統「通知頻道」選擇 **企業微信群組機器人**，貼上 Webhook 並儲存。
4. 點選頻道的「傳送測試」確認群組內收到訊息。

注意：

- Webhook 本身就是憑證，外洩後任何人都能向群組傳送訊息；外洩後請在群組內移除並重新新增機器人。
- 群組機器人不能接收 `/add` 等指令；需要指令請使用「企業微信智慧機器人（長連線）」。
- 單則訊息限制約 4096 位元組，系統會自動截斷，長清單可能顯示不完整。
- 群組機器人有頻率限制，觸發限流時系統會自動重試。

### 2.3 飛書自訂機器人

1. 開啟飛書群組 → 群組設定 → 群組機器人 → 新增機器人 → 自訂機器人。
2. 複製 Webhook 位址（通常形如 `https://open.feishu.cn/open-apis/bot/v2/hook/...`）。
3. 建議在安全設定中選擇 **簽章驗證**，複製簽章金鑰。
4. 在系統「通知頻道」選擇 **飛書機器人**，貼上 Webhook；如開啟簽章，填寫簽章金鑰。
5. 儲存後傳送測試訊息。

簽章規則（系統已實作，無需手動計算）：

- 時間戳為秒級。
- 以 `timestamp + "\n" + secret` 作為 HMAC-SHA256 的金鑰，對空字串計算簽章，結果以 Base64 編碼。
- 時間戳和簽章隨訊息主體一起傳送。

若使用「自訂關鍵字」或「IP 白名單」而不是簽章，請確認通知內容包含關鍵字，或將伺服器對外 IP 加入白名單。

### 2.4 釘釘自訂機器人

1. 開啟釘釘群組 → 群組設定 → 智慧群助理 → 新增機器人 → 自訂。
2. 複製 Webhook 位址（通常形如 `https://oapi.dingtalk.com/robot/send?access_token=...`）。
3. 建議在安全設定中選擇 **加簽**，複製加簽金鑰。
4. 在系統「通知頻道」選擇 **釘釘機器人**，貼上 Webhook；如開啟加簽，填寫加簽金鑰。
5. 儲存後傳送測試訊息。

簽章規則（系統已實作）：

- 時間戳為毫秒級。
- 以 `secret` 為金鑰，對 `timestamp + "\n" + secret` 計算 HMAC-SHA256，結果以 Base64 編碼。
- `timestamp` 和 `sign` 作為 URL 查詢參數傳送。

若使用「自訂關鍵字」或「IP 位址段」而不是加簽，請相應調整安全設定。觸發限流（例如錯誤碼 `90037`）時系統會自動重試。

### 2.5 事件訂閱與重試

通知頻道可以勾選訂閱的事件類型：

| 事件                | 說明                                           |
| ------------------- | ---------------------------------------------- |
| `release`           | 遊戲 / DLC 正式發售                            |
| `sale_start`        | 折扣達到監控門檻                               |
| `sale_change`       | 促銷期間的折扣或價格變化                       |
| `sale_end`          | 折扣結束、恢復原價                             |
| `price_change`      | 非促銷狀態下原價變化或免費狀態翻轉             |
| `delisting_warning` | Steam 新聞命中下架關鍵字（啟發式，需人工確認） |
| `delisted`          | 連續兩次確認商店無法購買                       |
| `restored`          | 恢復可購買                                     |
| `check_error`       | 檢查失敗                                       |

- **未勾選任何事件**時，預設接收除了 `check_error` 以外的全部事件。
- 傳送失敗會依 30 秒 → 2 分鐘 → 10 分鐘 → 1 小時 → 6 小時 → 24 小時重試，最多 6 次。
- 每個頻道卡片上有「傳送測試」，可用於驗證 Webhook 和簽章設定。

## 3. 指令機器人（雙向）

指令機器人讓使用者在飛書 / Lark、釘釘或企業微信聊天中透過斜線指令管理監控項目。飛書 / Lark 支援 HTTP 回呼或 WebSocket 長連線，釘釘支援 HTTP 回呼或 Stream 長連線，企業微信則透過 WebSocket 長連線；結果分別透過平台 API 或長連線回覆到原會話。

### 3.1 通用行為

- **作用範圍**：指令始終作用於機器人所屬帳號的資料。即使允許清單中的其他管理員使用機器人，也是修改機器人擁有者的監控項目。
- **擁有者識別**：`ownerPlatformUserId` 僅用於識別掃碼者 / 機器人擁有者，不會自動授予指令權限。
- **允許清單**：所有平台使用者（包括擁有者 ID）都必須加入允許清單才能執行指令，角色為：
  - `admin`：可使用全部指令。
  - `viewer`：只能使用 `/help`、`/list`、`/price`、`/events`。
  - 不在允許清單中的飛書 / Lark、釘釘、企業微信使用者都會收到一次性網頁授權連結，機器人不會執行原指令；釘釘同樣支援該連結。
- **事件通知**：機器人可以在編輯頁單獨開啟「接收事件通知」，把事件推送到最近一次被授權使用者使用的會話。它和「通知頻道」相互獨立，可以同時啟用。沒有最近會話時不會推送，詳見 3.5 節。
- **訊息格式**：目前只處理文字訊息。圖片、檔案、富文字、卡片訊息會被忽略。
- **指令格式**：以 `/` 或全形 `／` 開頭；支援 `/add@機器人`、引號參數、`--flag=value`。
- **去重**：平台重複投遞同一則訊息時，系統依平台事件 / 訊息 ID 去重，只處理一次。
- **限流**：每個平台使用者每分鐘最多 10 條指令，每個會話每分鐘最多 30 條，每個機器人每分鐘最多 60 條；觸發限流時每分鐘最多提示一次。
- **非同步回覆**：飛書 / Lark / 釘釘回呼會先快速回傳成功，釘釘 Stream / 企業微信訊息透過長連線接收；指令在背景執行，結果透過平台 API 或長連線回覆。平台顯示回覆可能會有少量延遲。
- **多結果選擇**：`/add`、`/adddlc` 依名稱搜尋命中多個結果時，機器人會回傳編號清單；直接回覆序號（10 分鐘內有效），或傳送 `/cancel` 取消。
- **配額**：每個帳號最多建立 3 個機器人；同一平台只能有 1 個啟用中的機器人（飛書與 Lark 國際版共用「飛書」平台名額）。飛書 / Lark / 釘釘的 HTTP 回呼機器人在停用後回呼位址立即失效（回傳 404）；長連線 / Stream 機器人在停用後連線會中斷。

### 3.2 飛書 / Lark 應用機器人 (建議)

> #### 建議理由
>
> 飛書/Lark 支援個人版，可以很好地將生活和工作分開。



飛書 / Lark 需要建立**企業自建應用**，開啟機器人能力並訂閱訊息事件。群組自訂機器人 Webhook 不能接收指令。飛書（中國版）使用 `open.feishu.cn` / `accounts.feishu.cn`，Lark 國際版使用 `open.larksuite.com` / `accounts.larksuite.com`；系統內透過機器人設定的「版本」區分。

#### 掃碼一鍵建立（建議）

1. 在「指令機器人」點選 **飛書 / Lark 掃碼**，在彈出視窗選擇「飛書」或「Lark 國際版」。
2. 用對應的用戶端掃碼；頁面會預填應用名稱並只允許建立新應用。
3. 確認建立後，系統自動取得 App ID / App Secret，寫入掃碼者 `open_id` 作為擁有者，並啟用長連線。
4. QR Code 10 分鐘內有效；同一平台已有啟用機器人或配額已滿時會被拒絕。
5. 在飛書 / Lark 中搜尋應用名稱開始一對一聊天，或將機器人加入群組聊天，傳送 `/help`。

> 掃碼建立使用飛書官方 `PersonalAgent` 範本，預先設定機器人能力、訊息權限和 `im.message.receive_v1` 事件，事件接收方式為長連線。若你的企業限制掃碼建立，可使用下方的手動設定。
>
> 若飛書 QR Code 被 Lark 租戶掃描，系統會自動切換到 `accounts.larksuite.com` 繼續完成授權。

#### 手動設定

1. 開啟[飛書開放平台](https://open.feishu.cn/app)或 [Lark 開放平台](https://open.larksuite.com/app)，建立企業自建應用。
2. 在「新增應用能力」中開啟 **機器人**。
3. 在「權限管理」申請訊息相關權限：
   - `im:message.p2p_msg:readonly`：讀取使用者傳給機器人的一對一聊天訊息。
   - `im:message.group_at_msg:readonly`：接收群組聊天中 @ 機器人的訊息。
   - `im:message:send_as_bot`：以應用身分傳送訊息。
   - 如後台依情境拆分權限，請同時申請讀取訊息內容、傳送訊息對應的權限。
4. 在系統中建立「飛書 / Lark 應用機器人」，選擇版本和事件接收方式：
   - **長連線（建議）**：在平台「事件與回呼」選擇「使用長連線接收事件」，訂閱 `im.message.receive_v1`；無需回呼位址。
   - **HTTP 回呼**：將系統顯示的 `/webhooks/feishu/<slug>` 填為請求位址；如需加密，填寫 Encrypt Key 與 Verification Token。
5. 建立版本並發布應用；在「應用可用範圍」中確保使用者可用。
6. 將機器人加入群組聊天，或直接與機器人一對一聊天。

#### 系統端欄位

| 欄位               | 是否必填          | 說明                                                             |
| ------------------ | ----------------- | ---------------------------------------------------------------- |
| 名稱               | 是                | 僅用於系統內識別                                                 |
| 版本               | 是                | 飛書（中國版）或 Lark（國際版）                                  |
| 事件接收方式       | 是                | HTTP 回呼 / 長連線；掃碼建立預設長連線                           |
| App ID             | 建議必填          | 取得 `tenant_access_token`、回覆和推送事件所需                   |
| App Secret         | 建議必填          | 與 App ID 配對                                                   |
| Encrypt Key        | HTTP 回呼時視平台而定 | 必須與飛書 / Lark 後台完全一致；啟用加密時必填               |
| Verification Token | HTTP 回呼時建議填寫 | 與平台一致；用於驗證事件來源                                   |
| 擁有者平台使用者 ID | 建議填寫         | 填飛書 / Lark `open_id`（通常以 `ou_` 開頭）；掃碼建立會自動填寫 |
| API Base URL       | 否                | 僅測試 / 代理使用；正式環境留空                                  |

#### 回呼、長連線與簽章

- **HTTP 回呼**：平台儲存事件訂閱位址時會傳送 `url_verification` 挑戰，系統會回傳 `challenge`。
  - 設定了 Encrypt Key 時，系統驗證請求標頭簽章 `SHA256(timestamp + nonce + encryptKey + rawBody)`，允許 ±300 秒誤差，然後解密密文。
  - 設定了 Verification Token 時，系統驗證事件中的 token；不符時回傳 401。
- **長連線**：伺服器端使用 App ID / App Secret 主動連線飛書 / Lark 的長連線端點；事件經已驗證的連線推送，不需要驗簽、公網位址或反向代理。連線狀態會顯示在機器人卡片上。
- 僅處理 `im.message.receive_v1` 中的文字訊息，忽略應用自身傳送的訊息。
- 回覆優先呼叫「回覆訊息」API；失敗時退回為向 `chat_id` 傳送訊息。
- 群組聊天中需要 **@機器人** 再輸入指令；一對一聊天可直接傳送。

#### 擁有者 ID 與允許清單

- 飛書 / Lark 事件中的使用者識別優先取 `open_id`，因此允許清單應填寫 `open_id`，不要填手機號碼、電子郵件或姓名。
- 掃碼建立會把掃碼者的 `open_id` 寫入「擁有者 ID」，但它僅用於識別，不會自動授予指令權限；首次使用仍需透過網頁授權核准自己的平台帳號。
- 手動設定時可查看事件偵錯 / 回呼日誌，或讓使用者先傳一則訊息後查看平台事件詳情。

### 3.3 釘釘機器人（HTTP 回呼 / Stream）

釘釘需要建立**企業內部機器人**，訊息接收模式可選 **Stream 長連線**（建議）或 **HTTP 回呼 / Outgoing**。釘釘自訂群組機器人 Webhook 不能接收指令。

#### 掃碼新增（建議）

1. 在系統「指令機器人」頁點選 **釘釘掃碼新增**。
2. 使用手機釘釘掃碼，選擇組織並依頁面提示填寫機器人資訊、確認建立。
3. 系統會自動取得 Client ID / Client Secret，以 Client ID 作為 Robot Code，並啟用 Stream 長連線；QR Code 10 分鐘內有效。
4. 建立成功後可在釘釘中搜尋機器人開始一對一聊天，或加入群組聊天；掃碼者 `staffId` 僅用於識別，使用成員仍需網頁授權或加入允許清單。

> 同一平台已有啟用中的機器人，或機器人配額已滿時，掃碼會被拒絕；請先在頁面處理舊機器人。
>
> 掃碼使用釘釘官方應用註冊頁。若組織限制掃碼建立，或註冊頁回傳異常，仍可使用下方的手動設定。

#### 手動設定

1. 開啟[釘釘開放平台](https://open.dingtalk.com/)，建立企業內部應用。
2. 在「新增應用能力」中新增 **機器人**。
3. 選擇訊息接收模式：
   - **Stream 模式（建議）**：在機器人設定中選擇 Stream 模式並發布；無需公網回呼位址。
   - **HTTP 回呼 / Outgoing**：填寫系統顯示的 `/webhooks/dingtalk/<slug>` 位址，並填寫 App Secret 用於驗簽。
4. 在系統中建立「釘釘機器人」，填寫 Client ID（App Key）與 Client Secret（App Secret），選擇相同的接收模式。
5. 如需推送事件通知，填寫 Robot Code（通常與 Client ID 相同），並確認應用具備機器人主動傳送訊息的權限。
6. 發布應用，將機器人加入群組聊天，傳送 `/help`。

#### 系統端欄位

| 欄位                        | 是否必填                | 說明                                           |
| --------------------------- | ----------------------- | ---------------------------------------------- |
| 名稱                        | 是                      | 僅用於系統內識別                               |
| 訊息接收模式                | 是                      | HTTP 回呼 / Stream 長連線；掃碼建立預設 Stream |
| App Key（Client ID）        | Stream 必填             | 釘釘應用 Client ID；事件通知也需要             |
| App Secret（Client Secret） | Stream 必填 / HTTP 驗簽 | Stream 建立連線憑證；HTTP 回呼用於驗證回呼簽章 |
| Robot Code                  | 事件通知建議填寫        | 機器人編碼；通常與 Client ID 相同              |
| 擁有者平台使用者 ID         | 建議填寫                | 填釘釘 `staffId`                               |
| API Base URL                | 否                      | 僅測試 / 代理使用；正式環境留空                |

#### 訊息接收與回覆說明

- **Stream 模式**：伺服器端使用 Client ID / Secret 主動連線釘釘 Stream 閘道，不需要公網 IP、網域或回呼位址；機器人訊息透過長連線推送，系統會立即 ACK 再非同步執行指令。
- **HTTP 回呼**：釘釘回呼請求標頭包含 `timestamp`（毫秒）和 `sign`；系統以 App Secret 為金鑰，對 `timestamp + "\n" + App Secret` 計算 HMAC-SHA256，允許 ±1 小時誤差。
- 兩種模式都只處理 `msgtype = text` 的文字訊息。
- 使用者 ID 優先取 `senderStaffId`，其次 `senderId`；擁有者 ID 和允許清單應填寫 `staffId`。
- 回覆使用訊息主體中的 `sessionWebhook` 傳送 markdown，並 @ 指令傳送者；該 Webhook 通常約 1.5 小時有效，過期後重新傳送指令即可。
- 系統依釘釘 `msgId` 去重；Stream 模式會額外立即確認推送，避免平台重複投遞。

#### 擁有者 ID 與允許清單

- 以回呼事件中的 `senderStaffId`（其次 `senderId`）為準；可在開放平台的事件偵錯日誌中查看，或在通訊錄成員詳情中核對。
- 「擁有者 ID」僅用於識別，不會自動授予指令權限；所有釘釘使用者都需要網頁授權或加入允許清單。
- 掃碼建立不一定會回傳掃碼者的 `staffId`，可手動補充；首次使用時讓機器人所屬帳號登入網頁核准即可。

### 3.4 企業微信智慧機器人（長連線）

企業微信需要建立**智慧機器人**並選擇 **API 模式 → 長連線**。企業微信群組機器人 Webhook 只能傳送，不能接收指令。

> 升級說明：舊版企業微信自建應用回呼（Token / EncodingAESKey / CorpID / AgentID）已不再用於指令機器人。既有機器人需要在「指令機器人」中改為填寫智慧機器人的 Bot ID / Secret 並儲存。

#### 掃碼新增（建議）

1. 在系統「指令機器人」頁點選 **企微掃碼新增**。
2. 使用具有建立智慧機器人權限的企業微信掃碼，依頁面提示建立並授權機器人。
3. 系統會自動取得 Bot ID / Secret，建立機器人並建立長連線；QR Code 5 分鐘內有效。
4. 建立成功後讓使用成員傳送指令，由機器人所屬帳號登入網頁核准；擁有者 UserID 僅用於識別，不會自動授予權限。

> 同一平台已有啟用中的機器人，或機器人配額已滿時，掃碼會被拒絕；請先在頁面處理舊機器人。
>
> 掃碼使用企業微信官方授權頁。若帳號沒有建立智慧機器人的權限，或企業微信調整了頁面流程，仍可使用下方的手動設定。

#### 手動設定

1. 開啟[企業微信管理後台](https://work.weixin.qq.com/)或企業微信用戶端工作台，進入「智慧機器人」→ 建立機器人。
2. 在建立流程中選擇「API 模式建立」→「使用長連線」。
3. 取得並儲存 **Bot ID** 和 **Secret**。Secret 通常只會顯示一次，遺失後可重新產生。
4. 在系統中建立「企業微信智慧機器人（長連線）」，填寫 Bot ID、Secret 和擁有者 UserID。
5. 將機器人加入群組聊天或一對一聊天；群組聊天中 **@機器人** 傳送 `/help`。
6. 無需填寫回呼位址、Token、EncodingAESKey 或 CorpID；服務會主動連線 `wss://openws.work.weixin.qq.com`。

#### 系統端欄位

| 欄位              | 是否必填 | 說明                                                                   |
| ----------------- | -------- | ---------------------------------------------------------------------- |
| 名稱              | 是       | 僅用於系統內識別                                                       |
| Bot ID            | 是       | 智慧機器人的唯一識別碼                                                 |
| Secret            | 是       | 長連線專用 Secret，用於 `aibot_subscribe` 驗證                         |
| 擁有者平台使用者 ID | 建議填寫 | 企業微信通訊錄中的成員 UserID；以機器人實際回呼中的 `from.userid` 為準 |

#### 長連線機制

- 伺服器端主動連線 `wss://openws.work.weixin.qq.com`，適用於內網部署，不需要固定公網 IP。
- 連線建立後傳送 `aibot_subscribe`，使用 Bot ID + Secret 完成身分驗證；之後每 30 秒傳送 `ping` 心跳。
- 使用者訊息透過 `aibot_msg_callback` 明文推送，無需解密；系統只處理 `msgtype = text`。
- 回覆透過 `aibot_respond_msg` 攜帶回呼中的 `req_id` 傳送 markdown；同一 `req_id` 的回覆依序傳送。
- 一個智慧機器人同一時間只允許一條有效長連線；新連線會把舊連線踢下線，多執行個體部署會互相中斷。
- 斷線會以指數退避重連；連續驗證失敗或連線被新執行個體取代時，機器人卡片會顯示長連線異常。
- 群組聊天訊息會先去掉開頭的 `@機器人`，再依斜線指令解析。
- 訊息回呼後 24 小時內均可回覆；系統在背景佇列中執行指令，長指令通常需要幾秒。
- 開啟機器人事件通知後，系統透過同一條長連線使用 `aibot_send_msg` 向最近會話主動推送；需要使用者先傳訊息給機器人。

#### 擁有者 ID 與允許清單

- 填企業微信通訊錄中的 **UserID**（成員帳號），不要填姓名、手機號碼或外部聯絡人 ID。
- 如果機器人建立者不是企業超級管理員，`from.userid` 可能是企業主體下的加密 userid；請以實際回呼事件中的值為準設定擁有者和允許清單。

#### 未授權與網頁授權

- 企業微信使用者不在允許清單時，機器人會回覆一次性網頁授權連結（`PUBLIC_BASE_URL/authorize/<token>`），30 分鐘內有效。
- 機器人擁有者使用自己的 Web 帳號登入連結頁面，核對平台使用者 ID（以及可用的暱稱、會話）後，選擇 `viewer` 或 `admin`，再核准或拒絕。
- 非機器人擁有者登入後只能檢視請求，不能自行核准；需要把連結轉傳給機器人擁有者。
- 授權連結處理一次後失效；同一使用者的其他待處理連結會同步更新。過期後請讓使用者重新傳送任意指令以產生新連結。
- 所有使用成員（包括掃碼者本人）都需要透過網頁授權或允許清單取得權限；如果希望自己擁有全部指令權限，請在核准時選擇 `admin`。
- `PUBLIC_BASE_URL` 必須可從瀏覽器存取；如果連結打不開，請檢查反向代理和該環境變數。

#### 連線狀態

機器人卡片會顯示長連線狀態：

- **長連線中**：正在建立連線或自動重連。
- **長連線已連線**：驗證成功，可以接收指令。
- **長連線異常**：憑證錯誤、未填寫 Bot ID / Secret、網路不可達、驗證失敗或連線被其他執行個體取代。
- **長連線未啟用**：機器人已停用。

若狀態持續異常，請檢查 Bot ID / Secret、伺服器對外防火牆是否允許 `wss://openws.work.weixin.qq.com:443`，以及是否有其他執行個體使用了同一個 Bot ID。

### 3.5 機器人事件通知

在「指令機器人」編輯頁勾選 **接收事件通知** 後，機器人會額外接收發售、促銷、下架等事件。它與通知頻道是兩套獨立設定，可以同時開啟。

- **通知目標**：機器人最近一次被允許清單成員使用的會話。系統只會在授權使用者成功傳送指令後更新該目標；未授權使用者不會改變通知目標。
- **前置條件**：目標機器人必須先收到過至少一條授權使用者的指令，否則不會產生事件投遞。機器人卡片會提示「尚未記錄最近會話」。
- **事件範圍**：接收全部事件，包括檢查異常；不支援依機器人單獨篩選事件類型。
- **通知頻道的群組機器人仍依通知頻道自己的事件勾選規則傳送，兩者互不影響。**

各平台的額外要求：

- **飛書 / Lark**：需要 App ID / App Secret，並具備以應用身分向會話傳送訊息的權限。事件會傳送到最近會話的 `chat_id`；HTTP 回呼與長連線模式均可。
- **釘釘**：需要 App Key、App Secret、Robot Code，並具備機器人主動傳送訊息權限。群組聊天使用 `openConversationId`，一對一聊天使用傳送者 `staffId`。
- **企業微信**：使用長連線 `aibot_send_msg` 推送到最近會話；一對一聊天 `chat_type=1`，群組聊天 `chat_type=2`。使用者必須先與機器人有過會話。

> 如果機器人被停用、事件通知開關關閉、最近會話被刪除或機器人被移出群組聊天，投遞會取消或失敗；重新讓授權使用者傳送一條指令即可重新整理目標會話。

## 4. 指令速查

```text
/help
/add <appid | 商店連結 | 名稱> [--discount N] [--note 文字] [--force]
/adddlc <基礎遊戲 appid | 連結 | 名稱> [--max 50]
/remove <id | appid | 名稱>
/pause <id | appid | 名稱>
/resume <id | appid | 名稱>
/check <id | appid | 名稱>
/price <id | appid | 名稱>
/list [--all] [--sale] [--paused] [--page N]
/events [--item id] [--limit 10]
/cancel
```

說明：

- `/add` 支援直接搜尋 Steam 商店；依名稱搜尋回傳多個結果時，回覆序號選擇。
- `--discount N` 設定折扣通知門檻（0–100），不填則使用帳號預設值。
- `--force` 用於目前地區無法取得、但仍想新增並只做新聞預警的情境。
- `/adddlc` 會匯入基礎遊戲的全部 DLC，單次最多 50 個。
- `/check` 會繞過快取立即檢查並寫入事件，會受 Steam 限流影響。
- `/list` 預設不顯示已暫停項目；`--all` 顯示全部，`--sale` 只看促銷中，`--paused` 只看暫停項目。
- `/events` 預設顯示最近 10 筆，最多 20 筆。
- 檢視者權限僅限 `/help`、`/list`、`/price`、`/events`。

## 5. 常見問題疑難排解

| 現象                                    | 可能原因                                                                                                            | 處理                                                                                         |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 飛書 / Lark / 釘釘儲存回呼位址失敗      | 服務無法從公網存取、憑證無效、`PUBLIC_BASE_URL` 錯誤                                                                | 用手機行動網路存取回呼網域；確認 HTTPS 憑證鏈完整；確認機器人已建立並啟用                    |
| 飛書 / Lark / 釘釘回呼回傳 404          | 機器人被停用、刪除，或 `<slug>` 填錯                                                                                | 在「指令機器人」頁面複製最新的回呼位址；啟用機器人                                           |
| 飛書 / Lark 提示挑戰失敗 / 401          | Verification Token 或 Encrypt Key 不一致；代理改寫了請求主體                                                        | 兩邊重新核對；關閉請求主體壓縮 / 重寫；保留 `X-Lark-*` 請求標頭                              |
| 飛書 / Lark 開啟加密後機器人沒有反應    | 平台開啟了 Encrypt Key，但系統未填寫，密文無法解析；也可能因 Verification Token 驗證直接回傳 401                    | 在系統填寫相同的 Encrypt Key 和 Verification Token，或關閉平台加密後重新儲存                 |
| 飛書 / Lark 能接收訊息但無法回覆        | App ID / App Secret 未填，或缺少傳送訊息權限                                                                        | 補齊憑證；在開放平台申請並發布訊息傳送權限                                                   |
| 飛書 / Lark 長連線一直顯示連線中 / 異常 | App ID / App Secret 錯誤；應用未開啟「使用長連線接收事件」；企業限制掃碼建立                                        | 核對憑證；在事件與回呼切換為長連線並發布版本；或改用 HTTP 回呼                               |
| 掃碼後搜尋不到飛書 / Lark 機器人        | 應用未發布或可用範圍不包含該成員                                                                                    | 在開放平台建立版本並發布，調整可用範圍；使用應用名稱搜尋                                     |
| 掃了飛書 QR Code 但建立的是 Lark 應用   | 掃碼帳號屬於 Lark 租戶，系統自動切換了授權網域                                                                      | 屬正常行為；到 Lark 中搜尋應用名稱即可                                                       |
| 釘釘回呼 401                            | App Secret 填錯；請求標頭被代理刪除；伺服器時間誤差超過 1 小時                                                      | 核對應用 App Secret（不是加簽金鑰）；保留 `timestamp`、`sign`；同步 NTP                      |
| 釘釘回覆逾時 / 失敗                     | `sessionWebhook` 已過期                                                                                             | 重新傳送指令；確保回呼在數秒內完成                                                           |

### 偵錯建議

1. 先使用系統「指令機器人」卡片中的 **模擬指令**，以機器人擁有者身分在本機執行，確認指令邏輯和配額正常。
2. 再使用「通知頻道」的 **傳送測試** 驗證 Webhook 和簽章。
3. 最後到平台聊天中傳送 `/help`，確認回呼 / 長連線、權限和回覆鏈路。
4. 查看容器日誌：`docker compose logs -f steam-monitor`，關注 `wecom`、`webhook`、`inbound`、`delivery` 相關日誌。

## 6. 安全性建議

- 飛書 / Lark / 釘釘回呼位址、群組機器人 Webhook、企業微信 Bot ID / Secret 都視為憑證，不要提交到公開儲存庫或發到公開群組。
- 飛書 / Lark 的 HTTP 回呼建議啟用 Encrypt Key + Verification Token；長連線憑證同樣需要保密。釘釘 HTTP 回呼必須填寫 App Secret 驗簽，Stream 模式也需保護 Client Secret；企業微信必須保護 Bot ID 與長連線 Secret。
- 允許清單遵循最小權限：一般成員使用 `viewer`，僅管理員使用 `admin`。
- 不要在公網暴露 SQLite 檔案；定期備份資料庫，並同時備份 `.env` 中的 `APP_SECRET`。
- 修改 `PUBLIC_BASE_URL` 或更換網域後，請及時更新飛書 / Lark / 釘釘後台的回呼位址；長連線模式不受影響。
- 懷疑憑證外洩時：飛書 / Lark 重設 App Secret / Encrypt Key，釘釘重設 Client Secret，企業微信重新產生智慧機器人 Secret，並在系統中重新填寫。
